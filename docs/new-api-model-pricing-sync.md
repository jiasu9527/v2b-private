# New API 全模型目录与统一人民币售价

这份说明描述可复现的**离线定价计划**，不是上线完成记录。工具不连接服务器、不读取 Key、不写数据库，也不自动启用渠道。

## 已确认的定价政策

- 普通用户统一使用 `default` 分组，倍率为 `1`，按实际用量扣 AI 余额。前端平台按钮是 OpenAI、Anthropic 等品牌分类，**不是计费分组选择器**。
- 按**每个模型**的可用正式分组取最高实际拿货价，再乘 `2.5`。只考虑该模型支持、且登录账号确实可用的分组，不取全站最高倍率套全部模型。
- 排除测试、试用、用户私有及未经核实的特殊分组。标注“勿选”的组默认排除，但标签不是运行可用性的证明；只有明确记录运行和账单核验理由后，才可重新审查指定组，不能整体忽略排除名单。
- 用户于 2026-11-11 更新政策：**不再售卖 Luna 模型，也不使用 Luna 专用分组**。模型名含 `luna`（大小写不敏感）一律记入 `blocked` 并说明原因，即使它同时出现在普通正式组或经过标签复核的组内也不会重新纳入；任何带 Luna 的分组也排除。旧 `--include-luna-for-all` 参数和 Python 同名开关传入 `True` 会直接报错，不能绕过新政策。旧计划若仍含 Luna 型号或专用路由，`attach_snapshot` 拒绝生成写入参数，必须重新生成计划。
- 只从输入的上游公开 `/api/pricing` 目录选择精确模型名，不根据官方模型名、前端静态资料或历史记录补造模型。公开存在仍不代表可售，已有故障隔离不能因本次排除 Luna 自动恢复。
- 目录未提供价格、渠道不可用、余额不足、仅特殊组可用的模型，列为待处理，**不能用模型列表存在来证明可售**。

## 人民币与内部 quota

本次已核验配置：源端实际 `¥1 = 500000 quota`；目标站历史余额的显示口径为 `¥7.3 = 500000 quota`。源端界面出现 USD 标签不代表成本需要再乘一次汇率；目标 `7.3` 在这里是既有 quota 显示单位，不能为了“全人民币”直接改成 `1`，否则已有余额购买力会变化。

目标内部价格系数为：

```text
源端该模型实际分组倍率 × 2.5 × 源端每 quota 单位人民币
÷ 目标每 quota 单位人民币 ÷ 目标用户分组倍率

当前 = source_group_ratio × 2.5 ÷ 7.3
```

例如 GPT 标准基础输入 `2`、输出 `10`，源正式组倍率 `0.17`，用户最终看到 `¥0.85 / ¥4.25` 每百万 Token。后端价格已经含 `2.5`，前端只按目标公开报价换算，不能再次加价。

以上单位是本次部署配置，不是所有 New API 的常量。迁移或修改显示单位前必须重新核验充值、余额、价格和原始 quota；脚本顶部常量需同步审查，不可照搬。

## 保留完整计价规则

- token `tiered_expr`：整体保留原始公式，只在最外层乘系数。上下文长度、服务档位、缓存读写（含小时档）条件都不得抹平。
- 含 `fixed()` 的按次／按图公式有专门 AST 约束，目标版本不接受任意外层常数。工具只对完整匹配 `tier(name, fixed(字面量))`（可追加 `* image_count`）的规则缩放叶子价格，保留图片数量；复杂固定计价树拒绝自动处理，需单独核实，不能生成前端可解析、后端却拒绝的公式。
- legacy token：只缩放 `ModelRatio`，保留输出／缓存／图片／音频相对比例；未提供的字段不伪造为零价。
- 按次：缩放 `ModelPrice`，保留明确的零价；不能一律转为 token 价格。
- 有插件计价覆盖时停止自动构建覆盖请求，人工核实插件规则。
- legacy 缓存字段缺失时，目标引擎的默认值可能与源端不同。应比较目标 preview 的有效配置和实际 usage，再决定是否发布。

## 离线计划工具

`scripts/new-api/pricing_plan.py` 只使用 Python 标准库。输入必须是去凭据的目录及已认证可用组快照，不能放登录响应、Cookie、Key、个人用户资料：

```json
{
  "origin": "https://upstream.example.invalid",
  "pricing": {"data": {"success": true, "data": [], "group_ratio": {}}},
  "groups": {"data": {"success": true, "data": {}}}
}
```

`pricing.data` 来自 `/api/pricing` 的 JSON；`groups.data` 来自已登录 `/api/user/self/groups` 的 JSON。脚本拒绝缺失成功认证组快照，账号组倍率优先于公开倍率。新增组名需更新并审核正式组白名单，不自动信任未知组。

```sh
python3 scripts/new-api/pricing_plan.py \
  --audit /absolute/path/sanitized-catalog.json \
  --output /absolute/path/pricing-plan.json

python3 -m unittest discover -s scripts/new-api -p 'test_*.py' -v
```

输出包含逐模型选组依据、排除原因、完整价格、源目录 hash 和 `verification_state=not_tested`。**计划不是渠道健康或实际计费证明**。测试使用六个合成模型，不依赖生产数据、网络或 `/tmp` 文件。

### 对标签与实际运行不符的分组做显式复核

`ds4` 的上游描述为“勿选”，所以默认计划仍排除它。2026-11-11 的真实测试中，该组 13 个模型有 12 个返回非空文本，账单使用组倍率 `1`；`gpt-5.2` 返回模型不支持错误。复核后可以将它纳入**定价候选**，但不能因此把全组直接标为可售：

```sh
python3 scripts/new-api/pricing_plan.py \
  --audit /absolute/path/sanitized-catalog.json \
  --output /absolute/path/pricing-plan-reviewed.json \
  --reviewed-group 'ds4=2026-11-11：已核对真实调用及倍率1的扣费记录；逐模型健康检查另存，失败模型不启用'
```

理由写入 `basis.reviewed_group_overrides` 及相关模型警告，不能为空；同一组不能重复指定。目前仅 `ds4` 在可复核标签白名单。该选项不能绕过账号实际组权限、模型支持组范围、价格校验，不能覆盖测试／私有／未知组，也不能取消全部 Luna 型号及路由的排除政策。仍先取最高价格；同价时优先原正式组，避免无谓切换到未验证的另一条路由。未来其他组需要先审查再修改白名单，不能把任意 `--reviewed-group` 当成放行开关。

同一去凭据目录快照在旧政策下曾生成默认 45/58、复核 `ds4` 后 58/58 的计划；这些是包含 Luna 的历史统计，不是当前可售目录。更新后的排除政策生成默认 **43/58**、显式复核 `ds4` 后 **56/58**，其中 `gpt-5.6-luna` 和 `gpt-6-luna` 明确列为政策排除。**这只是价格计划**，所有条目依然是 `verification_state=not_tested`。独立上游运行测试当时为 43 个成功、15 个失败（43 个包含 12 个 `ds4` 模型），需要按结果分别启用和隔离；移除 Luna 不会恢复那些故障模型。此计数是 2026-11-11 的时点记录，既不证明 Forest 用户链路已通过，也不保证今后的上游状态。

## 上线及回退顺序

1. 备份当前渠道及 `GET /api/option/model_pricing` 完整配置，凭据备份仅保存在受限目录，不进 Git。
2. 逐模型真实调用上游，区分文本、图片等所需端点；HTTP 200 空内容仍视为失败。故障模型不能因为有价格就启用。
3. 对待发布模型调用 `POST /api/option/model_pricing/preview`，核对有效配置和费用；不要提交整个未验证计划。
4. 重新 GET 定价快照，通过 `attach_snapshot(plan, snapshot)` 构建 `PATCH /api/option/model_pricing` 的 `changes`。这是**每模型完整替换**，不是字段增量；版本来自刚读取的 `version` / `empty_version`。
5. `409` 表示并发变化，重新读取核实差异，不盲换版本重试。需要回退时，也用备份完整配置配合最新 CAS 版本走同一接口，不能 raw SQL 绕过缓存及审计。
6. 建立对应专用上游 Key 的渠道，面向目标 `default`；只发布已验证可用模型。旧故障渠道应停用而非留作误接路由。
7. 用独立普通 Forest 测试号完成真实余额划转、同单重放、聊天和 API 调用；比较原始 quota 与实际 usage 合计，确认只扣 AI 余额、不会重复扣 Forest 余额。
8. 验证完整价格目录和各档报价。普通聊天仅接受文本模型，图片等显示“通过 API 使用”，不能混入聊天选择器。

上线报告必须分开列出目录总数、可映射价格数、实际成功数和上游阻塞数。历史验证不能保证上游未来始终可用，不能把未测试模型统称“全部跑通”。
