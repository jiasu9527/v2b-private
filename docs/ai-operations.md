# 后台 AI 运维

## 启用

更新 Go 后端与后台静态资源后，使用管理员账号进入 **AI 运维 → 设置**。员工可以进入 AI 运维进行对话、业务运维及 SSH 服务器管理；中转设置和全局清理仍由管理员维护。普通用户不能访问；接口每次重新核对管理员或员工身份，不使用 AI 独立 Token，也不需要 MCP 客户端。

1. 填入支持 OpenAI 兼容 **Chat Completions + tool calling** 的中转地址和 API Key。
2. 地址通常填 `https://relay.example.com/v1`；只填域名会补 `/v1`，也接受完整 `/v1/chat/completions` 地址。自定义前缀应填写到 `chat/completions` 之前。
3. 公网中转必须使用 HTTPS；仅本机回环测试允许 HTTP。服务不跟随重定向，避免 Key 被重定向到其他站点。
4. 模型 ID 每行一个，默认原样提供：
   ```text
   gpt-6.1-sol
   claude-fable-5-1
   deepseek-v4.1-flash
   glm-5.3
   ```
   不自动替换模型；中转必须实际开通对应模型及工具调用。聊天时可以切换模型。
5. 可分别配置每个模型的默认推理强度，未设置时使用“中转默认”。具体等级须由中转及对应模型支持，不根据模型名称推断能力。
6. 保存并启用后，发送简单的查询请求验证连通性。服务向 `/chat/completions` 请求流式响应，网页通过 SSE 实时显示回复；中转忽略流式参数并返回普通 JSON 时仍可兼容，但只能整段显示。

本模块默认关闭。首次访问自动创建 `v2_ai_*` 表并补齐缺少的字段，数据库账号须具备建表、修改表和建索引权限，无需运行整库安装 SQL。请保留并备份稳定的 `APP_KEY`；API Key、SSH 密码、私钥及私钥口令，以及新保存的知识正文和含凭据的知识保存请求，通过由它派生的 AES-GCM 密钥加密保存。丢失或直接更换 `APP_KEY` 将无法解密已有内容，不能靠重新启动恢复。

API Key 只写不读，留空保留；**修改中转地址必须重新输入 Key 或明确清除旧 Key**，不会将旧 Key 自动带到新地址。

## 每个模型使用不同中转

管理员进入 **AI 运维 → 设置 → 各模型独立中转**，为每个模型选择：

- **使用默认中转**：沿用上方默认 Base URL 和 API Key，老配置升级后仍按此方式工作。
- **独立中转**：填写该模型自己的 Base URL、API Key。比如 GPT、Claude、DeepSeek、GLM 可以分别使用四家服务商；也可以同一地址但使用不同 Key／分组。

聊天中仍然只需选择模型，网页和 Telegram 小程序共用后端路由，不必每次手工切换地址。所有服务商仍须兼容 OpenAI Chat Completions 和工具调用；本功能不把请求转换成各厂商的专有协议。

独立 Key 留空只保留**同一模型、同一规范化地址**的旧值，不能借模型改名或地址变化复用到其他服务。切回默认并保存会移除该模型的独立配置，再切回独立需重新填写 Key。所有模型均使用完整独立配置时，默认地址及 Key 可以留空；若仍有模型使用默认，默认配置必须可用才能启用 AI。

员工可选择已配置模型对话，但不能更改设置，也看不到独立中转地址或密钥。管理员接口只返回 `has_api_key`，不回显明文或密文；Key 加密保存。`has_api_key` 仍专指默认中转 Key，`ready_models` 表示具备完整主中转配置的模型列表，前端不会因为默认 Key 为空就误判所有独立模型不可用。

API：`config/save.model_endpoints` 按精确模型 ID 映射，省略字段保留原配置，显式 `{}` 清空全部独立配置；提供对象时整体替换。删除模型时应同时移除其独立配置。示例：

```json
{
  "enabled": true,
  "base_url": "",
  "models": ["gpt-6.1-sol", "deepseek-v4.1-flash"],
  "model_endpoints": {
    "gpt-6.1-sol": {"base_url": "https://provider-a.example.com/v1", "api_key": "填写 A 的 Key"},
    "deepseek-v4.1-flash": {"base_url": "https://provider-b.example.com/v1", "api_key": "填写 B 的 Key"}
  }
}
```

单项支持 `clear_api_key:true`，不能同时提交新 Key；AI 启用时不允许留下缺凭据的独立项。无独立配置的模型才使用默认中转；独立配置失效不会静默拿默认 Key 去请求。

## 模型与中转灾备

管理员在 **AI 运维 → 设置** 保留主中转地址和 Key，打开“自动灾备切换”，再添加备用中转。最多 4 个备用，按列表从上到下尝试，可上移、下移、单独启停或删除。每个备用分别填写名称、地址、Key 和支持的模型；模型留空表示继承全局模型列表，只会使用支持当前所选模型的备用站。

- 当前模型的主站优先（独立配置优先于默认）；遇到连接失败、超时、408／429／5xx、鉴权失败、明确模型未开通或额度不足时，切换到下一个可用站。响应格式损坏或流式中断也可切换，因为工具还未交给执行器。独立模型不会把全局默认站自动当作备用；需要时显式添加到备用列表，并选择支持的模型。
- 普通参数错误、推理强度不支持、重定向、用户停止及本地回复保存失败立即停止，不换站掩盖问题。这类错误不会自动换模型或降低推理强度。上游明确返回 `finish_reason=length` 时，仅提高当前回复的输出预算（4096 → 8192 → 16384）重新请求完整结果，保留同一模型、推理强度、上下文和工具定义；不会执行截断的工具参数。
- 优先尝试可用主备站；网络中断、空闲超时、408／429／5xx、空白回复等临时故障，同一站至多再试一次，并带短暂退避。鉴权、配额、模型权限和格式错误不会在同一站反复请求。故障后，对应模型在当前后端进程内冷却 60 秒；全部候选均冷却时，若配置了其他可用备用模型则直接尝试下一模型，否则本次请求可取消地等待最近一个恢复，不再立即报错退出，也不持续后台探测。多实例各自记录冷却，重启后清空。
- “响应空闲超时”默认 30 秒，可设 10–90 秒。等待第一段响应体时给予至少 90 秒宽限，避免推理模型尚未开始输出就被中断；仅收到响应头不算开始输出。开始接收响应体后，每次收到数据即续期，不再把整个流式回复截在 30 秒。单站模式也使用此空闲检测及有限重试。一次模型请求连同切站、等待及重试最多 5 分钟，防止上游只发心跳永久占用；完全访问没有整轮工具循环总时限，停止操作或权限撤回仍会取消等待。
- 切换只重试当前模型生成，不重新运行整轮任务，也不重放已经执行的后台／SSH 工具。备用站会收到当前对话及已完成工具结果继续处理。主站的半截工具调用不会执行，未完成正文在备用站开始前清空，不与备用回复拼接。

管理员可在 **备用模型顺序** 选择并上下调整模型。开启自动灾备后，先尝试当前模型的主备中转，均不可用再依次切换备用模型；留空保持仅切中转的旧行为。每个模型使用自己配置的 URL、Key 和管理员默认推理强度，不继承原模型专用参数。所有模型尝试共用一次 5 分钟期限，不会无限轮换。备用模型也会收到本会话上下文和工具结果，请只选择允许接收这些数据的平台。

切换成功后，回复显示“灾备已从 … 切换至 …”，本轮后续工具分析继续使用恢复后的模型；下一次发送仍从会话所选模型开始。只重新生成尚未完成的回复，不重放已完成的后台或 SSH 操作。旧配置的备用模型列表默认为空，需要管理员选择并保存；员工不能修改此设置。

所有 Key 加密保存，接口只返回是否已配置；留空按该备用站的稳定 ID 保留原 Key，调整顺序不会串用凭据。更换地址必须重填或明确清除 Key。员工可使用灾备后的对话服务，但不能配置，也看不到备用站地址、名称和 Key。切换不会额外逐条写入运维日志。

旧配置默认不开启灾备，也不自动创建备用站；更新后由管理员填写实际可用的备用地址和 Key 再开启。建议选择上游链路独立、确实支持相同模型及工具调用的中转，避免多个地址实际上共用同一个故障源。

## 推理强度

管理员在 **AI 运维 → 设置 → 各模型默认推理强度** 分别设置模型默认值，也可在 **运维对话 → 模型旁的“推理强度”** 调整当前会话的选择。员工不显示此选择器，发送消息时统一使用当前模型的管理员默认值，不能自行修改：

- **跟随设置**：按当前选中模型的后台默认值执行；切换模型时跟随该模型的默认值。
- **中转默认**：不向中转发送 `reasoning_effort`，由中转／模型采用其默认行为。这与关闭推理不同。
- **不启用推理、极低、低、中、高、极高**：分别发送 `none`、`minimal`、`low`、`medium`、`high`、`xhigh`。

设置影响下一次发送；管理员发送成功后会话保存所选项，重新打开时恢复。员工的旧会话即使保存过显式强度，下一次发送也会恢复为“跟随设置”；后端拒绝员工通过接口指定其他等级，完全访问模式也不能绕过。每一轮在开始时固定实际强度，该轮的全部工具调用循环使用同一值，中途修改后台默认不会改变已经运行的任务。旧会话默认“跟随设置”，旧配置默认“中转默认”。

等级支持取决于中转和模型；本面板只透传所选字段，不将它转换成 Claude、DeepSeek 或 GLM 的专有参数。上游明确拒绝推理强度参数时会提示改用“中转默认”或其他受支持等级，不自动降级、重发请求或重复执行工具。推理强度与“完全访问／逐次确认”权限无关，也不会显示模型内部推理内容。

## 对话显示

- 普通对话文字默认展开，支持粗体、列表、表格和代码块；每轮工具调用、参数、原始结果和执行记录合并在一个默认收起的“处理过程”中，展开一次即可查看，纯工具消息不显示空回复气泡。
- 对话顶部保留标题，模型、权限及管理员推理强度选择收进小设置按钮，不再常驻大块说明。手机端通过“历史”打开会话抽屉，选择后自动收起；聊天区域适配屏幕高度，输入区与发送、停止按钮保持可见，窄屏下选择项不会撑宽页面。
- **Enter 发送，Shift+Enter 换行**；中文输入法选字时不会误发送。
- 输入草稿由独立输入组件维护，逐字输入不重绘整段聊天历史；内容未变化的 Markdown 不重新解析。完成的会话不再每秒刷新，待审批操作仍及时更新过期状态。发送失败保留原文与重试标识，切换菜单保留未发送草稿。
- 轮询和 SSE 快照复用未变化的消息、动作和轮次；重复草稿不触发历史重绘。消息按轮隔离渲染，展开中的旧工具记录也不会随新回复重新构造。折叠的处理过程只保留摘要与审核入口，正文展开才挂载、关闭即释放；审核弹窗始终独立展示完整命令。手机历史抽屉关闭时不创建会话列表。
- Telegram 小程序输入框在支持的 WebView 中使用原生自动增高；旧 iOS 使用每帧合并的离屏测量，缓存尺寸样式，不重置选区或逐字切换真实输入框高度。输入区不做高度动画；键盘视口通知合帧处理，未变化的 CSS 和主题不重复更新。桌面输入框保持原有自动增高行为。
- 逐次确认模式下，折叠区旁保留“审核操作”入口；完全访问模式下，执行状态显示在过程摘要中，完整命令和结果位于同一展开区。实时更新不自动展开处理过程。
- 正在回复时增量显示文字，向上翻阅历史记录不会被强制滚回底部。切换会话或暂时断网不会取消后台任务。

浏览器 SSE 连接约 25 秒自动重连，连接不可用时回退到自动刷新。接口使用 `Authorization` 请求头，返回 `X-Accel-Buffering: no`；若前置代理仍强制缓冲，应为 `session/stream` 关闭缓冲。流式草稿每约 600 毫秒覆盖同一轮次记录，结束后清除，**不会按每个字符或分片新增日志记录**。工具参数必须完整接收且上游明确结束后才可执行，断流不会执行半截工具调用。

2026-11-02 输入性能回归：本地生产包、Chrome 390×844 移动视口、4 倍 CPU 降速、60 轮／240 条合成消息，连续输入 39 个中文字符。输入事件到后续两帧的中位耗时由约 100 ms 降到 20 ms，P95 由 136 ms 降到 33 ms；逐字触发的历史日期格式化从约 381 次降为 0。该结果是固定本地模拟场景，不代表所有手机的实际耗时。浏览器同时验证中文选字不误发、换行、失败保留草稿、重试幂等、成功清空及菜单切换保留草稿。

同日第二轮 iPhone/WebKit 专项回归：本地生产包、390×844 移动视口、100 轮／400 条合成消息，先空闲 11.5 秒覆盖两次轮询，再连续输入 70 个中文字符跨过刷新周期。相比上一轮版本，默认折叠页面 DOM 元素从 7148 降至 3798，不变轮询引起的历史日期格式化从 1268 次降为 0；WebKit 输入期间脚本读取 textarea 高度从 224 次降为原生尺寸模式的 0 次，强制旧 WebView 回退模式为 70 次。另用 Chrome 6 倍 CPU 降速复核。覆盖大段粘贴与缩回、键盘视口、菜单草稿、返回最新消息、上滑历史不被轮询打断、工具详情展开／释放；以上是本地模拟测试，并非用户 iPhone 实机测试。

## 入口诊断与精简回执（2026-11-02）

- `entry_health` 主表只返回入口状态、来源／探针计数，不再内联重复大数组；保留 `coverage_note`。它只覆盖**已配置监测**的入口，兼容字段 `unmonitored=0` 不代表没有漏监测。TCP 通畅也不代表低延迟或业务全链路正常。
- `entry_health_detail(key, section, limit, offset, revision)`：`section=sources/probes` 分别读完整来源／探针分页，每页默认 20、最多 50 条，按实际 `next_offset` 续读。返回拓扑 revision，后续页必须携带；拓扑变化返回 `conflict`，从第一页重读。探针观测是查询当时的值，不是历史快照。查询不刷新目标、不发检测、首次调用也不执行建表。
- `host_references(host, port?, limit, offset, revision)`：精确反查**当前入口分配候选地址**关联的规则、固定叶子、合集、节点和监测目标；每行一个 `{type,id}` 引用，避免二次嵌套截断。包括未配置监测、停用的来源；不传端口则列该 host 各端口。域名大小写、末尾点和 IPv6 规范化，不把域名解析 IP 当作原配置地址。
- `entry_coverage(gaps_only?, limit, offset, revision)`：独立检查覆盖缺口，不改变员工首页“未监测不显示”的设置。`source_gaps` 按启用来源计数，`address_gaps` 按启用来源的地址去重；同一地址被别的规则监测，不会抹掉本来源的漏配置。区分 `unconfigured`、`monitor_disabled`、`target_missing`、`target_address_mismatch`、`no_enabled_probes`，以及探针离线、观测缺失／过期等问题。`address_covered` 仅为结构覆盖，`address_observed` 表示该地址至少有新鲜明确观测，失败的 TCP 检测也算“已观测”，不等于健康。默认列覆盖缺口、观测不完整或 TCP 异常；`summary` 始终为全部候选统计。

上述反查／覆盖的端口是**已配置检测端口或候选建议端口**（见 `port_basis`），不是保证等于订阅连接端口；范围不含独立客户端入口、额外订阅节点、未关联规则节点，亦不代表历史实际下发全集。没有将当前配置反推成历史证据。分页超出单次输出体积时返回更少行，必须用 `next_offset`，不能自己加 `limit`。来源／引用分页校验拓扑与筛选集合版本；状态变化会使覆盖分页失效，延迟和时间等连续观测数值仍可能变化。

`entry_rule_detail` 新增可选 `revision`：先读 summary 取得版本，展开条件、值和节点时携带；`offset>0` 必须携带，规则版本在事务内比对，不符直接 `conflict`，不返回混合版本页。版本是 64 字符 SHA-256 值，不是自增编号，也不提供历史快照恢复。

`entry_monitors.save` 改走专用 `PUT /dns-failover/entry-monitors/save-receipt`，返回事务确认的 `committed`、新 `revision`、`saved_policy_count`、`saved_target_count`、`deleted_policy_count`；这些是完整保存后的数量，不是假称“仅改变字段”的 diff。提交后不再拉取整套概览，避免已保存却因后续读取失败被 AI 误报为写入失败。普通后台原保存接口和完整概览响应保持兼容。非管理员专属操作的小回执直接保存在原动作中，不再另建分块结果；大结果仍可通过 `panel_result_read` 续读，管理员专属结果仍保留权限校验。

**无条件规则确认**：新建 `conditions=[]`，或把原非空条件清空时，普通后台须勾选确认，AI／API须显式传 `confirm_match_all=true`。专用更新工具在 `changes` 中传，普通 `entry_rules.save` 在参数顶层传。确认只表示明确接受“所选节点范围全部合资格用户”的匹配，不改变权限组及规则优先级；不写入业务字段。已存在的无条件规则可继续原样编辑，`email in []` 仍是无人命中，不会变成全员。

## 权限与连续运维

对话窗口提供 **逐次确认 / 完全访问** 选项，新会话默认完全访问，操作人可主动切换逐次确认；已有会话保留原来的选择，不批量改写授权。

- **逐次确认**：修改配置、主动检测、SSH 命令先生成待确认卡，操作人逐项批准。
- **完全访问**：新会话默认启用，操作人保留此模式时，AI 可连续查询、修改、执行 SSH 并读取结果继续处理，无须每一步再次批准。使用已开放的运维工具与已登记服务器；不会凭空获得未登记服务器的凭据。
- **停止**：停止本轮后续处理并取消正在等待的请求／SSH 连接；已经完成的变更不会回滚，远程脚本可能已部分执行。切回逐次确认也会撤销本轮自动操作授权。

自动二分等业务开关只控制无人值守策略。明确要求手动二分时可执行一次，不要求先打开自动开关；只有明确要求长期启用自动策略时才修改开关。仍需满足用户数量、可用备用 IP、叶子状态及并发版本等数据条件。

授权按会话保存并绑定开启它的操作人；其他操作人不能继承自动执行授权。修改权限使用版本校验，旧页面、旧发送请求或重试不会恢复已撤销的权限。模型和工具输出不能修改权限。完全访问操作记录展示授权来源，不冒充逐条人工批准。

连续任务在后台运行，切换会话或关闭网页不会主动中止任务。完全访问不再因累计模型轮数、运行总时长或单会话消息数达到阈值而停止，可持续调用工具并处理结果，直到模型完成当前任务、用户停止、授权撤回或遇到无法继续的实际错误。执行结果未知时仍停止后续自动变更。SSH 命令明确结束但返回非零退出码时，按下述诊断流程继续，不直接结束整轮，也不原样重放失败命令。

运行中的完全访问任务使用后台自动续期的短租约，默认有效期 2 分钟；工作进程每秒检查停止与权限状态，每 20 秒续期。浏览器断线不影响续期；后端工作进程退出或无法确认权限时不会继续续期，租约到期后标为中断，不自动重放可能已执行的操作。单次模型请求、SSH 命令和业务接口仍各有超时，不能把持续执行理解为单条请求永不超时。

### 支付配置权限

支付通道配置不属于 AI 可访问的业务领域：不能查询、导出、添加、修改、删除、启停或排序，包括商户号、网关地址、密钥、证书、回调地址和通道手续费。即使由管理员发起对话或选择完全访问，也不开放此权限；支付配置仍由管理员在原后台页面手动维护。

第一方工具使用集中能力目录，工具声明、调用和动作提案／执行共同校验；未登记的工具、动作及支付配置领域默认拒绝。后台操作目录将明确登记的操作映射到已有处理函数，复用参数校验和业务逻辑；模型不能指定任意 URL、HTTP 方法或 SQL。通用配置读取必须指定已知非支付分类，写入只接受该分类目录中的字段，禁止通过配置接口绕过支付禁区。

后台非支付业务通过专用工具和可发现的操作目录提供给 AI。员工不能删除日志或会话、修改 AI 设置和推理强度，也不能通过修改账号身份或管理员密码提升权限；管理员可执行目录中的管理员专属操作。完全访问按同一目录自动执行写入，不需要逐条人工批准。

**SSH 的系统权限边界独立存在。** 模型指令明确禁止通过 SSH／脚本绕过支付禁区，但提示词和第一方工具目录无法限制登记账号在远程操作系统中的真实权限。如果面板或数据库服务器的 root 账号被登记，任意命令仍可能访问支付配置。本次不声称已建立服务器级支付隔离；要实现该边界，应仅接入不持有支付数据及访问凭据的独立节点／中转主机，或配置实际的系统账号、数据库和网络隔离。

## 能做什么

### 后台操作目录

除原有专用工具外，提供以下入口，避免模型把“没有同名专用工具”误判为没有后台操作能力：

| 工具 | 用法 |
| --- | --- |
| `panel_operations_list` | 按分类或关键词分页发现后台操作 |
| `panel_operation_describe` | 获取准确参数结构、读写类型和管理员限制 |
| `panel_query` | 调用目录中的只读操作 |
| `propose_panel_operation` | 提交修改、删除、发送通知或主动检测；完全访问自动执行，逐次确认待批准 |
| `panel_result_read` | 继续读取较大的响应，保留完整内容而非静默截断 |

覆盖用户及套餐、订单处理、工单、节点与权限组、入口分配、客户端入口、备用 IP 池、DNS 与故障切换、探针、订阅防护、公告和知识库、优惠券及礼品卡、邀请活动、统计与在线分布、系统日志、Apple ID 和迁移等后台业务。具体可用操作和参数以运行时目录为准；支付配置不列入目录，AI 自身的会话、权限和设置继续由原接口管理。

所有写操作都沿用动作记录、当前权限模式和停止机制。提案、审批、执行时重新验证操作与权限。后台通用操作复用原业务接口的并发约束，不额外承诺所有接口具备旧值快照；已有专用工具提供版本校验时应优先使用。结果未知时禁止自动重试写操作。

操作参数加密保存，审批详情只显示隐藏敏感字段后的预览，保存的工具调用参数也会隐藏凭据。超过单次工具输出容量的结果按当前会话保存为 30 分钟缓存，可按字符游标续读；读完一个结果分片并不等于读完后台列表，还需按该业务接口继续分页。删除会话时同步清理其结果缓存。

为完成实际部署，明确调用以下操作可读取任务所需的非支付凭据：创建探针返回该探针的新密钥和安装命令；`config.read` 的 `key=server` 且 `include_credentials=true` 返回节点安装所需 `server_token`；`nodes.list` 带指定 `node_id` 和 `include_install_command=true` 读取该 V2node 节点由后台生成的安装命令，保留自定义脚本与安装参数；指定 Apple ID 订单的交付查询返回该单账号内容。它们会进入该会话及配置的中转模型，普通列表和其他配置查询仍隐藏凭据。不能把这些专门操作用于读取支付配置，也不承诺任意聊天原文或流式输出都没有秘密。

### 自动查询

- 按完整邮箱或 ID 精确查询普通用户套餐、用量等信息。
- 查询套餐订单、节点基本配置及上报状态。
- 查询入口规则、二分叶子组，按邮箱与实际 UA 模拟当前入口匹配。
- 查询已有入口检测、备用 IP 健康与占用、调度和队列概况。
- 查询管理员或员工登记的共享 SSH 服务器列表。
- 查询普通用户的完整可编辑设置、余额和佣金，查询套餐与节点权限组供分配时使用。
- 分页查询全站工单、指定工单的消息及全站工单提交设置；管理员和员工均不必提供用户 ID，长消息支持分段续读。
- 查询入口检测目标、探针及指定检测任务的进度和逐项结果。
- 读取指定入口规则的完整可编辑配置、条件与生效节点，以及指定协议节点的连接配置和可编辑字段。

原有专用查询工具使用单独的字段白名单，不返回用户密码、订阅 Token/UUID、支付密钥或 SSH 登录凭据。节点部署和 Apple ID 交付的专门目录操作按上一节处理。专用列表一次查询默认 20 条、最多 50 条；模型传入超过 50 的整数 `limit` 时，按 50 条执行并在结果中返回生效值。负数、错误类型、未知字段和非法偏移量仍会拒绝。结果过长时自动缩小当页条数，并返回实际总数和下一页位置。单条超大规则的嵌套明细会明确标记截断。需按返回位置逐页继续，不应把一页当成全站数据；目录操作的分页参数以其描述为准。

#### 全站工单与提现申请

全站查询优先使用 `tickets_list_global`：`{"status":"open","reply_status":"all","limit":50,"offset":0}` 查询所有用户的未关闭工单，包括已回复但未关闭的工单。四项均必填：`status` 为 `all/open/closed`，`reply_status` 为 `all/pending/replied`，`limit` 为 1–50，`offset` 为 0–10000。这个工具不接受用户 ID 或邮箱，即使中转要求填完全部字段，也不需要编造用户身份或用 `0` 代替“全部”。只有明确查询待回复时才选 `pending`。

原 `tickets_list` 保留兼容：`{"status":0,"limit":50}` 仍可查询全站未关闭工单，`{}` 查询全部状态；`user_id`、`email` 是可选精确筛选，同时填写时取交集。`user_id:1` 永远只查询用户 1，不会静默改成全站。所有工单工具显式发送 `strict:false`，避免可选字段在支持该标志的中转上被默认强制化。

列表结果新增 `query`，显示实际 `scope`（`all_users/filtered_users`）、状态和生效的身份筛选；空页附带 `empty_reason`，区分无匹配、偏移超出总数和查询期间数据变化。空结果不能据此推断全站没有工单。按返回 `next_offset` 继续读取，列表按稳定的工单 ID 倒序排列。查询仍是实时数据，期间新增或关闭工单可能改变结果，不能宣称为某一时点的数据库快照。

同一轮对话中，只有完整空结果且筛选／分页和结果没有变化的工单列表才参与重复纠错：首次正常读取，重复时提醒模型核对范围；提醒后仍仅重复已有空查询，则保存已查范围与未完成说明并结束无效循环。新筛选、新结果、正常翻页或其他工具不会受该重复计数限制，下次用户发言重新计算。这不是恢复完全访问的总工具轮数或运行时长上限，也不会自动扩大用户指定范围或重试写操作。

取得工单 ID 后调用 `ticket_get`，按 `messages.next_offset` 读取消息列表。单条消息预览最多 2,000 字，返回 `total_characters`、`truncated` 和 `next_content_offset`；需要余文时调用 `ticket_message_get`，传 `ticket_id`、`message_id`、`content_offset`，可选 `content_limit`（默认及最多 2,000 字），按返回 `next_content_offset` 继续，偏移按 Unicode 字符计数。不能把消息预览当成完整申请。

提现申请与处理进展属于可读工单业务数据，支付配置禁区不会阻止此类查询。系统自动生成的提现工单通常只记录提现方式、账号，未保存申请金额快照；原文没有金额时应标注“未注明”，不能用用户当前佣金余额冒充申请金额。统计须去重并说明读取范围，金额结论保留工单／消息依据。

### 按当前权限模式执行

- 使用 `ssh_server_register` 将操作人在当前会话提交的 SSH 资料登记到服务器列表。工具只接受后台生成的 `intake_id`、可选名称和原因，不接受密码或私钥；逐次确认待审核，完全访问自动登记并返回 `server_id`，可继续检查连接和部署。
- 修改指定节点的连接配置，按协议支持名称、地址、订阅连接端口、监听端口、节点权限组、倍率、显示状态、TLS/SNI 和传输设置等。先通过 `node_detail` 获取当前配置及可编辑字段，再调用 `propose_node_update`；旧 `propose_node_change` 仍兼容。
- 修改入口规则／二分叶子组的入口 `host`，保留 UA 条件、固定用户名单等。合集中的成员不能单独修改，非叶子组不能直接改。
- 编辑现有入口规则的名称、启用状态、排序、分配动作、用户 ID／邮箱／套餐／注册天数／UA 条件、生效节点和入口设置；使用 `entry_rule_detail` 读取后，再用 `propose_entry_rule_update` 提议。条件与节点列表是整项替换，未传字段保留。二分与合集继续遵循后台现有约束，不通过修改来源条件重建固定分配。
- 使用 `propose_entry_split` 直接二分标准规则或固定名单叶子，不依赖自动二分开关或探针故障判定。标准规则支持用户 ID 范围加 UA，UA 条件保持；新入口可从健康备用 IP 池原子领取两个，或明确指定两个不同地址。使用最新 `entry_rule_detail` 的版本，至少两名用户，完成后返回两个子组及地址。
- 使用 `entry_split_options`、`propose_entry_manual_split` 按已有故障判定与等待策略二分；自动开关关闭也能手动请求，不会开启永久自动化。缺少健康备用 IP 时保留任务等待，通过 `entry_split_operation` 查询原因及最终状态，不能把受理当完成。
- 使用 `propose_entry_auto_split` 开启或关闭指定叶子的自动二分。仅明确要求修改长期策略时调用；沿用后台的检测状态重置和旧任务取消逻辑。
- 发起指定规则的检测；检测结果仍遵循原后台自动化配置，**可能触发现有自动切换／二分逻辑**。
- 在已登记服务器上执行完整 SSH 命令，包括只读诊断、部署节点、修改服务配置。
- 修改普通用户的套餐、节点权限组、总流量配额、有效期、设备数、限速、封禁状态、余额／佣金余额、折扣／返佣设置和备注；可以明确重置已用流量。
- 关闭、重新开启或回复指定工单；回复全文保留在操作详情中，按当前会话权限模式执行后，通过现有后台流程通知用户。
- 将全站工单提交切换为“所有用户可提交”“仅付费用户可提交”或“关闭”。这与关闭单个工单是两种不同操作。
- 向指定入口目标、指定探针派发一次检测；未指定探针时使用启用的探针。随后可按返回的 `run_id` 查询进度和结果。

AI 通过工具提出具体动作，后端根据当前会话权限执行。逐次确认模式等待操作人审核；完全访问模式复用相同的配置校验、幂等及执行流程，完成后把实际结果交给模型继续处理。权限只接受有权操作人的网页操作，模型没有切换权限或自行批准的工具。

用户修改只影响明确选择的字段；选择套餐会带出该套餐的权限组、配额、设备数和限速，审核表展示最终生效值。有效期和已用流量保持原值，除非显式指定修改／重置。流量按字节、金额按分传入，均为最终绝对值。封禁用户会撤销已有登录会话。权限组指节点访问组，与入口规则中的邮箱分组不同。

这批工具对管理员和员工开放，同一套工具和完全访问执行流程不因员工身份降级；员工只能访问自己的对话和操作记录，管理员可以查看和管理全部。用户修改工具面向普通用户，不处理管理员／员工角色、密码和订阅密钥；服务器命令继续使用已登记服务器。工具不提供数据库 SQL 或任意内部 API 透传。

主动检测的审批卡包含实际入口、端口和探针范围；受理任务不代表检测已通过。探针尚未上报的项保留为待完成，不能当作成功。检测上报仍会遵循原来的自动切换、自动二分配置。历史 `monitor_run` 工具仍可按规则发起检测。

动作有效期 15 分钟。审批使用配置快照校验；目标节点、入口条件、固定名单或 SSH 服务器身份发生变化后，旧操作会拒绝执行，应重新分析生成提案。并发或重复批准只会有一次实际执行。

用户和工单变更在同一数据库事务中保存动作结果；目标设置、套餐或工单回复发生变化时旧提案失效，正常流量上报不使用户提案失效。全站工单开关使用原配置文件的原子保存和运行时重载，保存中断时标记结果待核对，不自动重试。

## 登记服务器

可以直接在聊天中发送一台服务器的 SSH 资料，例如：

```text
帮我登记这台中转服务器，然后检查 54101 端口。
192.0.2.10:2222
root
example-password
```

也支持中英文标签形式（地址、端口、用户名、密码）。每条消息一台，未指定端口时使用 22。使用 `ssh user@host -p 2222` 格式时，密码须单独标注 `password:`，不能与待执行命令混淆。标签冒号后的单个空格视为格式分隔；密码本身含首尾空格时可使用 JSON 双引号，例如 `password: " space-preserved "`。支持完整私钥及私钥口令；模型不需要接触这些凭据。

后台在发送给模型前解析支持格式，凭据加密暂存，聊天、标题及工具参数仅保存隐藏后的信息与 `intake_id`。检测到无法完整识别的凭据资料时会拒绝发送，提示补齐字段。暂存资料有效期 24 小时，绑定提交操作人和会话，删除会话会一并删除；已登记服务器独立保留。此机制不替代对任意聊天文字或命令输出的秘密检查。

登记前先进行不带凭据的 SSH 握手观察。提供主机指纹时必须匹配；未提供时固定首次观察到的指纹，操作详情标明“首次连接记录”，后续连接必须匹配。登记仅保存连接配置，不代表已认证登录或节点工作正常。同一资料重复提交登记工具不会重复建服务器；相同地址、端口和用户名已存在时拒绝覆盖，需在服务器页面维护已有配置。

也可使用原有表单：

进入 **AI 运维 → 服务器 → 登记服务器**：

- 填名称、主机地址、SSH 端口、用户名、密码或私钥。
- “获取主机指纹”只进行握手观察，不使用密码登录，也不会自动信任观察到的指纹。
- 通过可信服务器控制台等独立渠道核对 `SHA256:...` 主机指纹后填写并保存。
- 正式连接必须匹配已保存指纹；不匹配会在认证及命令执行前拒绝。
- 修改主机、端口、用户名或指纹时，旧凭据不会隐式复用；重新填写连接凭据。

不读取面板宿主机的个人 SSH Key、SSH 配置或系统凭据；不会在面板本机 Shell 执行模型命令，只通过登记目标的 SSH 会话发送按当前模式授权的原始命令。

服务器列表中的 **部署／配置** 会打开带目标服务器的聊天草稿。可描述落地节点或中转服务需求，提供安装脚本来源、端口和目标配置；AI 先检查系统与已有服务，再创建可审核的完整命令。

SSH 为非交互执行，不提供键盘输入或交互终端；脚本须使用已核实的非交互参数。部署按“检查 → 明确配置 → 备份 → 执行 → 验证”逐项进行。`propose_ssh_command.timeout_seconds` 默认 120 秒，可选 30–1800 秒；审核窗口展示执行上限。最多同时执行 2 条 SSH 命令，输出上限 32 KiB。执行中每秒至多覆盖一次当前动作的输出，页面实时同步，默认仍折叠，**不按输出分片增加日志行**。延长执行不会被旧的三分钟超时检查误判结束。

SSH 建连阶段会自动处理临时故障，完全访问和逐次确认后执行均适用：

- TCP 连接、SSH 握手或会话创建阶段发生可识别的暂时网络错误（EOF、连接重置、连接拒绝、网络超时等），**且尚未发送命令**时，自动最多尝试 3 次连接；第 2、3 次分别等待 1 秒、2 秒。重连成功后在同一个动作中执行原命令并继续本轮，不需发送“继续”，不额外创建审批动作。
- 重连进度保存在原动作输出中，成功和耗尽次数可在“执行记录”查看。每次失败的连接立即关闭；退避、连接和执行共享原动作的总超时，不会不断重置计时延长任务。
- 明确密码/密钥认证失败、主机指纹不匹配、协议/算法不兼容不自动重试，分别返回安全原因；不再把所有握手错误都显示成“认证或指纹失败”。上游原始错误、远端 banner 和凭据不进入提示。
- 每次重连前和发送命令前重新校验停止状态及操作授权；停止、撤回权限或总超时到达时中断。达到重连次数仍失败时明确提示命令未发送，不无限尝试。

命令发送后，完全访问模式继续区分两类 SSH 失败（自动重连不覆盖这一阶段）：

- **明确非零退出码**（例如 `1`）：保存为失败动作，并记录结构化 `exit_code`。将具体错误和输出返回模型，跳过同批尚未执行的后续工具，让模型先检查现状、核对是否部分修改，再在原任务范围内修正命令并验证；无需为此重新发送“继续”。发送给模型的摘要从已保存输出中保留开头和结尾，并明确标记省略；SSH 采集仍保留原有 32 KiB 上限。
- **断线、超时、未取得确定退出状态**：仍按结果未知处理，停止后续自动执行。权限撤回、用户停止、认证失败及无法确认动作状态也会停止，提示具体动作号和原因，数据库原始错误不回显。

同一轮对同一登记服务器，已非零退出的同一命令（忽略首尾空白）不会被原样再次执行；调整原因或超时不能绕过此检查。它不是 Shell 语义分析器，语义等价但写法不同的命令仍需模型依据输出和现状判断。不再以累计失败次数停止整个任务：不同的诊断或修正命令可继续执行，重复失败命令会返回拒绝原因供模型继续分析，原有失败动作及退出码仍保留。逐次确认模式仍逐项审批。

历史动作没有 `exit_code` 时不会根据中文错误文案猜测为可继续，不会自动恢复旧的失败轮次。更新后由用户继续原会话，模型可按最新动作结果核对现状。

### 其他操作的临时故障重试

自动重试由后端执行，网页和 Telegram 共用，无需额外开关；恢复成功会继续本轮，不需要反复发送“继续”。大多数重试最多 **3 次尝试（首次＋2 次重试）**，退避 **1 秒、2 秒**，仍受原请求或动作的总超时约束。

- **只读工具**：已审查的用户、工单、节点、入口、订单、知识及后台目录查询遇到临时网络／数据库故障，或查询接口返回 `408/429/500/502/503/504` 时自动重试。每次重验权限和操作目录；不把名字像“查询”但会刷新监测目标或创建动作的接口当纯查询重放。永久参数、权限、配置冲突和数据库结构错误不重试。
- **事务内变更**：用户、节点、入口、工单、服务器登记及二分的专用动作，在 PostgreSQL 明确报告事务回滚（`40001/40P01`）或审批前会话锁暂忙时，复用原动作重试审批事务。每次重新锁定、比对快照和权限；不会新建另一条动作。普通业务忙、版本冲突或提交结果未知不会进入此重试。
- **检测任务**：入口探针与监测任务使用持久化请求键 `ai-entry-probe:<actionID>`／`ai-action:<actionID>` 去重。临时故障重试沿用同一键；即使首次已创建任务但响应丢失，也只返回原 `run_id`，不重复下发。
- **状态／权限检查**：轮询动作状态、检查撤权与停止、续期及 SSH 发送前检查遇到短暂数据库故障，会在原 3 秒检查预算内最多尝试 3 次，间隔 100／200 毫秒。明确撤权或停止立即中断；持续无法核实权限仍停止，不绕过权限检查。
- **完成状态回写**：操作结束后若保存结果短暂失败，只重试原动作的条件 `UPDATE`，不重跑实际业务。不会因一次状态回写失败就永久停在“执行中”，也不会复活已删除的会话或覆盖已保存的终态；持久故障仍可能需要核对。
- **不盲重放**：SSH 已发命令、普通后台写请求、提交结果未知且无可靠幂等键时，仍先核对现状。参数错误需要修正，重复写入、重复扣款／回复／创建节点不能靠无条件重试解决。重试不增加逐次日志行，也不自动恢复历史失败轮次。

### DNS / 后台操作失败后的继续处理

- DNS 记录查询、新建、修改、删除和启停会按准确域名核对服务商的 `DomainId`；需要线路时使用实际套餐 `Grade`。模型遗漏 ID 或等级时由后端只读补齐，不再把付费 `Global` 线路按免费套餐查询。提供的域名与 ID 冲突时拒绝写入。
- **确定未执行**：域名元数据或线路预检查遭遇明确临时故障时，先在原动作内最多尝试 3 次，每次重查权限、停止与目录快照；只有可信 `NotExecuted + Retryable` 信息可启用此机制。参数不合法、域名／线路不存在、凭据错误不重试。前置故障最终未解决时记录为 `failed`，保存服务端生成的 `not_executed` 标记。完全访问模式会把安全诊断交给模型，跳过当前批次后续工具，让它查询并修正参数；同一轮不允许原样重放已失败的操作和参数。节点本地参数校验失败使用相同的模型修正机制。
- **执行结果未知**：DNS/其他后台写请求发送后遇到网络错误或不明确的 HTTP 错误，动作仍为 `unknown`，不会假称成功。AI 可以继续查询现状、形成核验总结，但本轮进入后端强制的只读模式，不能再新建记录、改入口、发探针检测、写知识或执行 SSH。即使模型说“已完成”，本轮仍标记为待核对的失败轮次；查不到记录不能当作写请求从未执行。
- 恢复阶段仅开放已核验的查询工具和后台查询操作；新工具、新目录操作不会自动获得恢复权限。带有刷新监测目标或远端订阅入口副作用的“查询”也会阻止。正常查询所需的结果保存或缓存不等于业务变更。
- 只有内部类型化的执行阶段信息能证明“未执行”；不会信任上游响应正文、HTTP 状态码或模型文字中的同名字段。错误摘要只包含固定安全说明，不透传凭据、SQL 或上游原始错误。
- 更新不会自动重放旧的失败动作。对旧会话发送“先查询失败操作的实际结果，再继续原任务”即可重新核对；用户停止、授权撤回和 SSH 断线保护继续有效。

部署中断或连接断开可能已部分执行，标为结果未知后需核对，**不会自动重试，也不保证远程回滚**。不要在未核对的脚本中写入凭据，或让命令输出整份秘密配置。安装完成后还应检查服务、端口及业务连通性；命令受理或开始下载不等于部署成功。

## 会话与数据清理

管理员可查看和删除全部会话，包括所有员工的会话；员工只可查看、使用、停止和审批自己的会话，不能删除会话、清空全局数据或修改中转配置。完全访问模式也不会开放会话删除权限。不会另建逐条查询日志，聊天与动作结果本身就是本模块的操作记录。

| 操作 | 删除范围 |
| --- | --- |
| 删除某会话 | 该会话、消息、生成轮次、待确认及已完成操作记录；仅管理员可执行 |
| 清空全部会话 | 所有管理员和员工的会话及其附属记录，仅管理员可执行；保留中转配置和服务器 |
| 重置全部 AI 数据 | 上述全部会话数据 + 中转配置/Key + SSH 服务器配置/凭据；须输入 `RESET_AI_DATA` |

清理仅删除 `v2_ai_*` 模块记录，不删除用户、订单、节点、入口规则，也不会撤销已批准的业务变更。

有远程操作正在执行时，删除该会话或清空／重置会拒绝；等待操作结束或核对中断状态后再清理。正在生成的 AI 对话可以删除，后台会停止后续生成和持久化，不会复活已删除会话。进程意外重启后，超时执行记录显示“结果未知”，不能据此认定远程没有执行。

数据库删除不等于擦除备份、WAL、代理记录或中转提供商已经收到的数据。**聊天文字、业务查询结果、命令以及有限输出会发送到管理员配置的中转站**；中转和模型保留策略由管理员选择的平台决定。本模块只会过滤它已知的 SSH 凭据原文，不保证任意远程输出都没有秘密。

## 跨会话共享知识

后台「AI 运维 → 共享知识」用于保存站点架构、服务器用途、网络关系、部署步骤和排障经验。支持关键词搜索、分类、常用标记及 Markdown 正文；条目显示版本、更新时间、操作人及来源会话／轮次。可直接在聊天中说“把这次核实的架构整理进共享知识”，AI 会先检索已有条目再保存；不会自动把全部聊天内容搬进知识库。

- **管理员**：可新增、编辑、发布草稿、停用、删除；管理员会话里的 AI 保存后直接共享。
- **员工**：可读取已共享知识及本人草稿，手动或通过 AI 新建草稿；不能修改已有条目、发布、停用或删除。草稿经管理员发布后才供其他会话使用。
- AI 提供 `knowledge_search`、`knowledge_get`、`knowledge_create`、`knowledge_save` 四个工具。新文章优先使用 `knowledge_create`，其 schema 不包含 ID／版本字段，后端也拒绝这两个字段，因此不能覆盖旧文章。`knowledge_save` 继续支持同时省略 `id` 与 `expected_version` 来新建；更新时才同时提供真实正整数 ID 与版本，单独提供一个、`0` 或 `null` 均拒绝。成功返回新／原 ID、`version` 及 `active/draft` 状态供核对。
- 知识工具在实际模型 HTTP 请求中显式使用 `strict:false`，`knowledge_save.required` 不包含 ID／版本；无需中转为可选字段补值。检索和阅读只返回已发布知识；来源会话和轮次由后端写入，模型不能指定或伪造。修改、删除仍校验 `expected_version`；AI 更新冲突返回 `knowledge_version_conflict`，同一轮相同更新内容重复提交返回 `knowledge_conflict_repeated`，不再写入。若本意新建，改用 `knowledge_create`；确需更新则重新读取、核对并合并，不能只换版本号覆盖旧内容。后台编辑冲突继续保留尚未保存的输入。
- 每次模型请求重新读取最新目录，优先加载常用条目和部分正文；含部署凭据的条目只列目录，不自动展开正文，当前任务需要时由 `knowledge_get` 按权限读取原文。该块最多 14,000 字节，最多列出 24 条，其余通过工具搜索及分页读取，避免挤占当前问题。资料通过独立的上下文数据消息提供，不作为系统指令，也不重复存入聊天记录。修改、停用、删除会影响后续模型请求，已发出的请求及历史对话中的旧内容不会被追溯抹除。
- 知识与会话独立保存：删除单个会话、清空全部会话均保留知识；管理员「重置全部 AI 数据」会同时删除知识。没有外部向量数据库或额外摘要模型调用。
- 安装脚本可在正文中保留部署 key／token，无需另开开关或手动删除参数。新写入的正文自动加密；明文列只保存去敏检索内容，标题、摘要和来源说明也会去敏。授权详情及 `knowledge_get` 解密返回原脚本，供查看、修改和部署复用。旧正文保持兼容，下次保存时升级为加密格式，不额外重写历史数据。
- 这里的加密范围是知识正文和相关原始知识保存请求，不改变 SSH 操作记录的存储方式。执行命令本身携带的部署 key 仍可能出现在授权操作详情或远程程序输出中；不得据此声称所有执行记录、任意输出或旧备份都已去除凭据。
- 明确要求保存到知识库的含凭据脚本，不会再被当作不完整 SSH 登记拦截；原请求加密保存，会话展示及知识工具的持久化记录隐藏凭据，当前任务的模型上下文仍可使用原文。跨轮工具历史提示按知识 ID 重新读取，避免把隐藏后的值当成真实安装参数。普通 SSH 登记仍使用专用加密暂存流程，不改变支付禁区和员工权限。
- 最多 500 条，每条标题 120 字符、摘要 500 字符、正文 12,000 字符。AI 单次保存正文最多 6,000 字符且参数总计不超过 32 KiB；长知识按独立主题拆分。变量占位符可原样保留。共享正文由有权访问该知识的运维人员及按需读取的中转模型使用，不是仅管理员可读的密码保险箱；仍不要保存支付配置或无关的用户私人数据。

## 容量及接口

- 最多 200 个会话、200 台登记服务器；完全访问不再以单会话 4000 条消息为停止或拒绝继续的条件，逐次确认仍保留该容量检查。页面显示最近 400 条，较早记录未显示时会给出提示，旧记录仍保存在数据库；显示窗口不影响后台继续运行。
- 模型上下文优先保留当前请求、最新工具结果和最近 10 个动作摘要；超过预算时按完整轮次／完整工具批次省略较早上下文，不删除聊天或操作记录。工具调用与结果成组保留，避免丢失配对。模型会获知数据被省略，必要时重新查询。
- 最多 4 个并发生成任务，每个会话同时 1 个；逐次确认最多 6 次工具分析、120 秒。完全访问不设置累计模型轮数或总运行时长上限，通过短租约续期确认工作进程仍存活，并持续响应停止和权限撤回。
- 请求携带 `request_id` 做发送幂等，重试同一内容不要换 ID；审批不可重放。
- 所有接口使用既有管理员／员工登录会话，`Cache-Control: no-store`，不支持匿名或外部模型直接调用。

接口前缀为 `/api/v1/<后台路径>/ai-ops/`：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET / POST | `config` / `config/save` | 获取无密钥配置（员工可读启用状态、模型列表及默认强度）/ 仅管理员保存配置；`reasoning_efforts` 按模型 ID 配置默认值 |
| GET | `sessions`、`session?id=...` | 可访问会话 / 消息、轮次及操作详情；员工仅本人 |
| GET | `session/stream?id=...` | SSE 实时快照与回复草稿；员工仅本人会话 |
| POST | `session/create`、`chat/send` | 建立会话 / 异步生成（202）；管理员的 `reasoning_effort` 可选 `default`、`auto` 或上述等级，员工仅可省略或传 `default`；新会话默认 `full`，可显式带 `access_mode: "standard"` |
| POST | `session/access` | `{id,mode,expected_version}` 切换逐次确认 `standard`／完全访问 `full` |
| POST | `chat/stop` | `{id}` 停止当前会话任务及后续自动操作 |
| POST | `session/delete`、`session/clear`、`reset` | 仅管理员可执行，须显式确认清理 |
| GET / POST | `servers` / `server/save` | 服务器列表 / 保存加密凭据 |
| POST | `server/fingerprint`、`server/delete` | 观察指纹 / 版本校验删除 |
| POST | `action/approve`、`action/reject` | 人工确认（202）/ 拒绝 |
| GET | `knowledge` | `query`、`category`、`status` 可选筛选；`current=1`、`page_size=20`（最大 100）；列表不包含正文 |
| GET | `knowledge/detail?id=...` | 查看一条可访问知识的完整正文与版本 |
| POST | `knowledge/save` | 新增／管理员编辑；字段 `title,summary,content,category,status,pinned`，编辑还需 `id,expected_version`；员工新建强制草稿且不置顶 |
| POST | `knowledge/delete` | 仅管理员，`{id,expected_version,confirm:true}` |

知识分类为 `architecture/server/network/deployment/troubleshooting/other`，状态为 `draft/active/disabled`。列表响应为 `{data:{data:[条目],total,current,page_size}}`，详情和保存响应为 `{data:条目}`。AI 搜索通过 `next_current` 翻页，正文通过 Unicode 字符偏移 `next_content_offset` 续读。上述接口继续使用现有登录、后台权限与禁止缓存设置。

`config/save.reasoning_efforts` 示例为 `{"gpt-6.1-sol":"high","claude-fable-5-1":"auto"}`，未列出的模型使用 `auto`；整个字段省略时保留现有模型的配置，显式 `{}` 重置为中转默认。管理员的 `chat/send.reasoning_effort` 省略时沿用当前会话选择，新会话为 `default`；员工始终解析为 `default`，显式指定其他等级返回 403。返回的 `session.reasoning_effort` 是所选项，`turn.reasoning_effort` 是本轮实际解析值。

`config/save` 支持 `failover_enabled`、`failover_timeout_seconds` 和 `fallback_relays`。例如：

```json
{
  "enabled": true,
  "base_url": "https://primary.example.com/v1",
  "models": ["gpt-6.1-sol"],
  "failover_enabled": true,
  "failover_timeout_seconds": 30,
  "fallback_relays": [
    {
      "name": "备用站一",
      "base_url": "https://backup.example.com/v1",
      "api_key": "填写该站的 Key",
      "models": ["gpt-6.1-sol"],
      "enabled": true
    }
  ]
}
```

新增项不传 `id`，保存后返回服务端生成的 ID；编辑时携带该 ID，`api_key` 留空保留，`clear_api_key: true` 清除（启用的站点仍必须有 Key）。省略 `fallback_relays` 保留原备用配置，传 `[]` 清空；省略开关及超时字段也保留原值。移除全局模型时，需同时更新显式引用该模型的备用配置。

### 常见中转错误

- **工具分片编号／ID 错误**：属于中转流式格式解析，与之前已成功的工具查询无关。流式工具编号作为关联标识处理，允许非零起始、大编号和稀疏编号；省略编号时，仅按唯一 ID 或唯一调用关联。重复的完整 ID／名称可兼容，参数仍按原片段拼接。不同调用无法区分、负数编号或响应不完整时，不执行该次回复里的任何工具；较早轮次已完成的操作不回滚、不重放。单次回复可包含最多 64 个实际工具调用，数量与编号数值无关，完全访问可在后续批次继续，不限制累计轮数。

- **401**：Key 无效或过期。
- **403**：权限、IP 白名单或中转防火墙拒绝访问。
- **`model_not_found` / `model_not_available`**：当前 Key 所属分组没有该模型，即使中转站其他分组支持也不能调用。后台会明确提示“所选模型在当前 API Key 分组不可用”，不会自动改用别的模型。
- **429**：频率／并发受限，或额度不足；明确的额度错误会单独提示。
- **普通 404**：核对 Base URL 和模型 ID。
- **HTTP 500 / 502 / 503 / 504**：中转或上游服务返回错误，界面保留实际 HTTP 状态；需结合中转服务状态排查。模型请求失败不等于本轮较早的操作未执行，应查看操作结果，不能盲目重试。

后端只识别有限的错误代码，返回固定中文提示，不把中转错误正文或它可能回显的密钥写入会话。

失败或中断后发送“继续”，会带上最近失败轮的原始用户请求及未完成说明，避免丢失任务。失败轮的工具片段不重新发送，已执行操作以最新动作摘要为准；不会因为模型请求失败就自动重新执行操作。

### 上下文提示

旧版本的“对话上下文不可用或过长，请新建会话”把历史读取故障与上下文大小限制混为一谈。新版会自动收缩发给模型的历史上下文；数据库读取失败单独提示，不再一律要求新建会话。上下文收缩不增加汇总模型调用费用，不删除原始消息，也不会批准或重试操作。

### IP 池批量删除参数与恢复

`ip_pool.delete_many` 的 `scope` 为必填枚举：`selected`、`faulty`、`all`。只替换用户指定的故障名单时，应先从 `ip_pool.list` 核对真实条目 ID，再使用 `{"scope":"selected","ids":[180,181]}`，一次最多 500 个；不能擅自扩大到全部故障或全池。`faulty` 仅匹配已确认 `unhealthy` 的条目，不等于未知或探针过期；`faulty/all` 不接受非空 `ids`。

在请求解码或纯参数校验阶段被拒绝，后端通过内部可信标记返回 `ip_pool_invalid_arguments`、`execution_state=not_executed`、`recovery=panel_preflight`，AI 可查询现状、修正参数并继续；不会自动原样重放失败请求。操作已交给业务层后出现的异常、事务提交或连接结果不明，仍保留 `unknown` 和本轮只读恢复，不能把所有 HTTP 400 当作未执行。历史 unknown 动作不会被此更新自动改状态或重跑。

删除仍会校验占用，查看 `deleted`、`skipped_in_use`、`skipped_not_found` 确认结果。删除 IP 池条目不删除服务器网卡地址、策略路由或独立监控；这些变更应分别核对和执行。

只读恢复按轮次生效，不是会话永久锁。发给模型的系统上下文明确标明当前 `turn_id`，动作摘要携带获准执行的 `authorization_turn_id`（手动审批或旧记录缺失时为 `0`），防止历史错误中的“停止后续写入”被误当成当前轮次的永久限制。用户发送新消息继续时，先查询实际状态，再在原授权范围内仅对核实后尚未完成的差异重新规划；无法确认的相关操作继续暂停。历史 `unknown` 保留、不自动重放、不伪造完成；本轮新发生的结果未知仍立即进入只读恢复，不能通过 SSH 绕过。

### 长任务上下文与原始约束保留

当前消息历史预算为 240000 JSON 字节、最多 160 条消息；包含工具定义后的完整中转请求上限 512 KiB。这不是 token 配额，不等于模型宣称的上下文窗口。完整历史加载最近 10 个 completed/pending 轮次，另读取最近 50 个已结束/待确认轮次的用户原始请求；失败轮次不加载残缺工具对话。压缩时先清理旧工具过程和回答，软保留近期用户原始请求（最多 16000 字节，且不超过本次消息预算四分之一），再按必要空间继续压缩。原始请求保留 user 身份，不提升为系统指令；过长的请求不截成半段脚本。当前用户输入、系统权限、动作状态仍受保护；软保留不是永久记忆，无法容纳时旧内容仍可能省略，跨长期会话的稳定架构信息应使用共享知识。此次不扩大中转请求上限或修改模型本身的 token 能力。

### AI 使用后台历史 IP 名单二分

`entry_split.preview` / `entry_split.create` 现在暴露后台页面已支持的历史参数。先通过 `panel_query` 查询 `entry_split.preview`，传 `history_host/history_from/history_to`；将返回的 `history_host/from/to/snapshot_hash` 原样对应到创建请求的 `history_host/history_from/history_to/snapshot_hash`。历史模式不用 `minutes`，不能替换成近期任意订阅用户；名单由后端重查并用 hash 校验，不用模型回传全部用户 ID。`entry_evidence.delivery_users` 可分页核对历史身份。创建传明确的共同 `members`、名称、A/B入口；`history_single_group=true` 时只建一个组并省略B。创建独立规则不需要删除旧规则或解除合集关系。

这只是补齐现有页面接口的 AI 契约，不新增永久快照ID，不自动继承不同来源的UA，也不自动完成特殊规则保护排序。新规则默认追加，需读取当前顺序、保留指定置顶规则，必要时排序并按真实用户/UA/节点模拟验证；未验证不得声称已生效。若无法用共同节点/条件表达用户要求的差异，应说明边界而非扩大范围。

### 入口规则与固定叶子的相对排序

旧 `entry_rules.sort` 对应后台拖拽保存，是完整全表替换：`items` 必须包含全部普通 `policy` 和当前叶子 `split_group`（含停用项），不能仅传新建 A/B；二分父容器和历史非叶子不参与全局排序，`policy_id` 不是叶子 ID。工具 schema 现已明确 `kind` 枚举与这个全量约束。

AI 调整少量分组优先使用：

1. `panel_query` → `entry_rules.order`，分页读取真实 `kind/id/name/policy_name/sort` 和全表 `revision`。后续页传 `expected_revision`，不一致返回 409，不能拼接不同版本；该只读操作也允许在本轮只读恢复时核对。
2. `propose_panel_operation` → `entry_rules.move`，传 `items`（要移动的 A/B 叶子，最多 100 项）、`after`（目标锚点，如用户指定的特殊置顶规则）和 `expected_revision`。例如 `{"items":[{"kind":"split_group","id":201},{"kind":"split_group","id":202}],"after":{"kind":"policy","id":7},"expected_revision":"从order取得的64位版本"}`，ID 只是格式示例，不可据此执行。
3. 后端在同一排序锁与事务中核实版本和可见项，按 `items` 次序插到 `after` 后，保留未选行相对顺序。不会删除原规则、更改条件、节点、固定分配或合集。相同位置用最新版本提交返回 `changed=false`，不重复写。
4. 成功后回读顺序，按真实用户、节点、UA 模拟验证分流。仅修改顺序不代表已经证明最终下发，特殊规则必须选对真实锚点，不能用名称推测 ID。

纯参数校验拒绝或前置版本/可见项冲突通过内部可信标记返回 `entry_order_invalid_arguments` / `entry_order_conflict`、`not_executed/panel_preflight`，可查询、修正后继续，禁止原样重放；业务写入或事务提交结果不明仍为 `unknown`，不能把普通 HTTP 400/409 或返回文本伪装成未执行。旧 unknown 动作不会被此更新自动改状态或重跑。无需前端构建或新增数据表。
