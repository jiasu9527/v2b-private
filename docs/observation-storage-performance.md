# 访问统计：大日志查询与日分区存储

## 页面与查询

- 默认查询最近 15 分钟，只加载明细和节点覆盖；不自动计算全站全天汇总。
- 明细最多读取 `page_size + 1` 条，再关联用户邮箱，不先执行全量 `COUNT(*)`。
- `/observation/events` 返回 `has_more`、`next_cursor`、`total_exact`。`total_exact=false` 时 `total` 只是已知下限，不是总条数。下一页传入原筛选和 `cursor`，修改筛选或每页条数必须重新开始。
- 游标按 `occurred_at,node_id,event_id` 倒序继续，不受新到达的较新事件造成的 OFFSET 位移影响；这是实时日志查询，不保证分页期间迟到或过期清理的数据形成固定快照。
- 汇总由管理员主动计算，与明细独立；翻页不重复汇总。汇总最多同时执行一项，12 秒超时；明细 15 秒、节点覆盖 5 秒超时。过大汇总应缩短范围或指定用户、目标，不返回假零值。
- 域名和 IP 分别使用精确域名、目标 IP 索引，不对完整日志使用模糊文本查询。
- 数据库初始化只缓存成功结果；临时锁冲突或请求取消不会永久停掉后续查询和上报。

## 存储切换

- 原 `v2_node_observation_event` 保留，升级时不复制、不重写大表。
- 新报告写入 `v2_node_observation_compact`，按事件时间的 UTC 日分区；保留原事件时间和每次路由尝试，不按分钟合并。
- 32 位小写十六进制事件 ID 使用 17 字节可逆编码；旧格式原样保留，不截断。恒定字段通过视图恢复，不重复存储。
- `v2_node_observation_history` 合并新旧记录，旧记录仍可查询。每节点报告事务锁以及跨分区 ID 查重保持重试幂等。
- 必须替换单实例，不应长期混跑写旧表的旧二进制和写新表的新二进制。
- 预建过去 7 日至次日分区。只删除整个过期 UTC 日，分区名字和真实边界必须一致；短锁超时、schema 限定且不使用 CASCADE。
- 查询仅开放最近 7 天；未归档分区最多保留 7～不足 8 天；开启下面的无损归档后，热表逐步缩到约 12～36 小时。过渡期旧表额外占空间：旧记录全部归档或过期后才加锁复核并整体释放，不能宣称升级立刻回收旧表。

## 容量与回退

第一阶段同批 10 万条样本含索引实测约节省 33%，不是所有流量的容量承诺。磁盘还需给旧表、WAL、临时排序和其他业务留余量；日分区并不解决无限增长速率。

部署前保留旧二进制和前端 release 链接。回退旧二进制不会删除 compact 数据，但旧版本页面无法读取新表，且新写入会回到旧表；需要继续使用兼容新旧表的查询版本，不能把单纯回退称为无损功能回滚。不要删除新表，也不要全表迁移或重置数据库。

## 验证

`OBSERVATION_TEST_DSN` 和 `FOREST_OBSERVATION_TEST_DSN` 可指向可丢弃的本地 PostgreSQL；集成测试使用独立 schema，覆盖新旧混查、IPv6、跨日和并发重试幂等、游标同秒边界、到期清理及跨 schema 安全。

前端：`node --test admin-src/scripts/test-access-statistics.mjs`（需从 admin-src 运行相对路径），覆盖明细与汇总解耦、翻页不重算、超时、取消和失败保留当前页。

## 无损冷热归档（2026-11-18）

- 最近 12 小时（取整点，实际 12～13 小时）保留逐行热数据；每分钟维护最多压缩 40 秒，积压时逐步追赶。
- 更早、仍在七天保留期内的事件按**用户＋UTC 小时**分块，每块最多 10,000 条。使用版本化 MessagePack＋gzip，原事件 ID、精确时间、地址、端口和历史字段全部保留；不按分钟合并、不丢弃测速域名、不减少用户范围。
- 压缩块保存在同一 PostgreSQL 的 `v2_node_observation_archive`，附带域名／IP／节点候选索引。SHA-256、gzip CRC、解码字段回比全部成功后，插入压缩块与按物理元组身份精确删除源行在同一事务提交；失败则保留源记录。
- 明细与汇总跨热表和冷块使用 repeatable-read 快照，并先锁定热关系，避免空表 TRUNCATE 的非 MVCC 行为造成漏读。冷块先按元数据筛选，再解码逐条过滤；不会把块内不匹配事件计算进去。明细超时 15 秒，汇总仍受 12 秒、单并发和内存界限保护；大范围应指定用户或目标。
- `(node,event_id)` 重试幂等跨冷热保留。Bloom 仅用于跳过确定不存在的块，阳性必须解码确认。只缓存不可变块的 Bloom 元数据，不缓存正文；重启后按节点懒加载，不在第一条上报时读取全站七天元数据。归档提交必须持独占 advisory lock `(582791,1)`，上报持 shared lock，且自增块 ID 必须在独占锁之后生成；不要绕过该协议写归档表。
- 七天到期按压缩块清理，边界小时内部仍按精确事件时间过滤；普通 VACUUM 将空间重用。热日分区与旧堆表只有**全部为空、加锁再次核实**后才 TRUNCATE 物理回收；有迟到数据则保留。因按日分区，磁盘热占用不一定恰好 12 小时；旧表尚有近期记录时也不能立刻回收整表。
- 不能回退到不认识归档表的版本，否则历史页面会漏掉已压缩数据。压缩块属于原始证据的唯一已提交表示，禁止为了回退删归档表。备份需要完整包含该表。

容量需以 `pg_total_relation_size`（含 TOAST 与索引）实测，不以纯 gzip 比例承诺。七天 Bloom 按当前流量估计约 1.8 GB 常驻缓存，各节点首次重建会额外读取其元数据；应观察进程 RSS、上报耗时、归档追赶速度、WAL 与磁盘余量。
