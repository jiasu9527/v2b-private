# 访问统计：大日志查询与日分区存储

## 页面与查询

- 默认查询最近 15 分钟，只加载明细和节点覆盖；不自动计算全站全天汇总。
- 明细最多读取 `page_size + 1` 条，再关联用户邮箱，不先执行全量 `COUNT(*)`。
- `/observation/events` 返回 `has_more`、`next_cursor`、`total_exact`。`total_exact=false` 时 `total` 只是已知下限，不是总条数。下一页传入原筛选和 `cursor`，修改筛选或每页条数必须重新开始。
- 游标按 `occurred_at,node_id,event_id` 倒序继续，不受新到达的较新事件造成的 OFFSET 位移影响；这是实时日志查询，不保证分页期间迟到或过期清理的数据形成固定快照。
- 汇总由管理员主动计算，与明细独立；翻页不重复汇总。汇总最多同时执行一项，12 秒超时；明细 8 秒、节点覆盖 5 秒超时。过大汇总应缩短范围或指定用户、目标，不返回假零值。
- 域名和 IP 分别使用精确域名、目标 IP 索引，不对完整日志使用模糊文本查询。
- 数据库初始化只缓存成功结果；临时锁冲突或请求取消不会永久停掉后续查询和上报。

## 存储切换

- 原 `v2_node_observation_event` 保留，升级时不复制、不重写大表。
- 新报告写入 `v2_node_observation_compact`，按事件时间的 UTC 日分区；保留原事件时间和每次路由尝试，不按分钟合并。
- 32 位小写十六进制事件 ID 使用 17 字节可逆编码；旧格式原样保留，不截断。恒定字段通过视图恢复，不重复存储。
- `v2_node_observation_history` 合并新旧记录，旧记录仍可查询。每节点报告事务锁以及跨分区 ID 查重保持重试幂等。
- 必须替换单实例，不应长期混跑写旧表的旧二进制和写新表的新二进制。
- 预建过去 7 日至次日分区。只删除整个过期 UTC 日，分区名字和真实边界必须一致；短锁超时、schema 限定且不使用 CASCADE。
- 查询仅开放最近 7 天；compact 正常维护时物理保留 7～不足 8 天。过渡期旧表额外占空间：最后一条旧记录过期后才加锁复核并整体释放，不能宣称升级立刻回收旧表。

## 容量与回退

同批 10 万条样本含索引实测约节省 33%，不是所有流量的容量承诺。磁盘还需给旧表、WAL、临时排序和其他业务留余量；日分区并不解决无限增长速率。

部署前保留旧二进制和前端 release 链接。回退旧二进制不会删除 compact 数据，但旧版本页面无法读取新表，且新写入会回到旧表；需要继续使用兼容新旧表的查询版本，不能把单纯回退称为无损功能回滚。不要删除新表，也不要全表迁移或重置数据库。

## 验证

`OBSERVATION_TEST_DSN` 和 `FOREST_OBSERVATION_TEST_DSN` 可指向可丢弃的本地 PostgreSQL；集成测试使用独立 schema，覆盖新旧混查、IPv6、跨日和并发重试幂等、游标同秒边界、到期清理及跨 schema 安全。

前端：`node --test admin-src/scripts/test-access-statistics.mjs`（需从 admin-src 运行相对路径），覆盖明细与汇总解耦、翻页不重算、超时、取消和失败保留当前页。
