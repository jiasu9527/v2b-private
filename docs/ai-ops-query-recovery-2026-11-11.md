# AI 运维入口查询重复与工具参数超长修复

## 已核实的故障链

生产只读核查（2026-11-11；未修改线上配置或触发检测）：

- 会话 59、轮次 694：在第 429 次模型请求失败，此前执行 428 次工具调用。
- `entry_probe_targets` 调用 277 次；把规则 ID 或 `1` 当作 `target_id`，与 `policy_id` 同时过滤后为空。同参数最多重复 123 次，探针心跳变化不代表查询取得进展。
- `host_references` 调用 132 次；其中把监测配置数字版本 `71` 当作拓扑字符串 revision 的相同请求重复 118 次。
- 最终错误为工具参数超长。旧版没有保存失败输出的工具名和参数字节数，不能反推最后是哪一个工具，也不能认定是流式中转重复拼接。
- 另外两个查询轮次分别在第 3、11 轮报同类错误，因此参数超限也可能单独发生，不能把所有错误都解释为长会话。

页面“最近 400 条”仅为显示窗口，不是模型上下文上限；现有模型历史预算为 240000 字节、160 条消息，请求总上限 512 KiB。完全访问授权属于当前操作者，不可因处理查询错误而继承另一操作者授权。

## 修复范围

1. **精确参数提示**
   - 检测目标首次只传已核实的 `policy_id`；`target_id` 必须来自真实返回，未知时省略。
   - 空结果附纠正说明，不自动扩大筛选，不把空结果当正常或故障。
   - 入口拓扑 revision 首次省略，分页使用同接口、同查询范围返回的 64 位小写十六进制值；与检测配置数字版本区分。
   - 检测与入口查询工具显式 `strict: false`，保留可选筛选字段的可省略语义。

2. **本轮查询无进展保护**
   - 仅针对已确认的两类结果：空检测目标，以及入口反查的参数／版本错误。
   - 第 2 次重复开始提示纠正；继续连续重复至第 5 次时结束空转并保留证据不足说明。
   - 忽略参数键顺序、调用 ID、探针心跳变化；不拦截正常翻页、真实结果变化、其他有效工作或异步检测结果轮询。
   - 不设整个会话的累计工具次数上限；新用户请求重新计数。

3. **工具参数超长的有限纠正**
   - 保留普通工具 16000 字节、扩展工具 32768 字节上限。
   - 返回安全工具名、实际字节数和上限，不返回参数正文或任意上游名称。
   - 同一 completion 最多一次要求模型精简参数；跨模型／中转共用该次数，在原五分钟期限内处理。
   - 原任务、历史和已执行结果不变；不截断 JSON，不执行部分工具，不重放已执行动作，不把超长误判成中转故障冷却。
   - 二次超限明确结束，正常取消与授权校验仍保留。
