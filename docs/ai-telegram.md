# Telegram AI 运维

Telegram 是现有 AI 运维的入口，不是另一套 AI。推荐通过 **Bot 小程序（Telegram Mini App）** 使用网页对话、会话历史、模型选择、服务器、共享知识与执行记录。原私聊文字保留兼容；模型、中转灾备、工具和后台权限均复用现有服务。

## 小程序启用（推荐）

1. 更新代码、重启 Go 后端并更新管理员静态资源。数据表自动初始化。
2. 原有 Telegram 设置中启用 Bot。小程序优先使用已配置的 **Telegram Webhook 地址**所在域名，未配置时才使用网站地址 `app_url`；地址必须是可公开访问的 HTTPS 地址，同域能够访问 Go 后端的 `/ai-ops-mini` 和 `/api/v1/ai-ops-mini/*`。前后端分离时应填写指向 Go 后端的 Webhook 地址，避免误用仅托管用户前端的域名。
3. **AI 运维 → Telegram** 中启用接入，点击“更新 Webhook”；管理员为自己／员工生成一次性绑定码，让对应人员私聊 Bot 发送 `/aibind <code>`。已经完成独立运维绑定的账号不用重绑。
4. 点击 **安装／更新 Bot 小程序菜单**，把 Bot 菜单配置成“AI 运维”。只发送配置中的固定网站地址，不发送后台登录凭据。也可私聊 `/aiapp` 或 `/miniapp` 获取启动按钮。
5. 从 Bot 菜单进入小程序，自动校验 Telegram 身份，无需输入后台密码。第一次未绑定、绑定已撤销或没有管理员／员工角色的用户不能进入。

小程序使用 `https://<配置的后端域名>/ai-ops-mini`，不展示完整后台导航。不是把后台登录 Token 拼在链接里，也不根据客户端的 `initDataUnsafe.user` 授权。

- 服务端验证 Telegram 官方 `initData` 签名和时间窗口，再核对独立运维绑定，换取仅限 AI 运维 API 的临时凭据（最长 8 小时）。凭据在浏览器中只存内存、在数据库只保存哈希，不写入普通后台登录存储。
- 每个请求重新检查绑定、账号角色、开关与 Bot 身份；流式输出持续复核。解绑／停用会拒绝新请求并停止关联任务，不回滚已发生的远程变更。
- 小程序和网页显示同一套会话。默认完全访问，仍能切换逐次确认；员工不能修改全局设置、推理强度或删除会话，管理员可查看／删除全部会话。
- 小程序凭据不能登录普通后台、支付配置或其他用户接口。支付配置仍不向 AI 工具开放。
- 切换到手机后台、临时断网后的身份重验保留当前会话和输入草稿；关闭／刷新整个页面不会保存草稿。关闭小程序不会自动停止已提交任务。
- 反向代理必须把上述页面/API路径转发给 Go 服务，不能误交给用户前端 SPA。不要对小程序页面额外添加 `X-Frame-Options: DENY/SAMEORIGIN` 或禁止 Telegram Web 的 `frame-ancestors`；普通后台页面策略无需放宽。

绑定设置中的默认模型、权限和通知开关继续控制**私聊通道**。小程序沿用网页 AI 运维的模型与权限选择，聊天结果在小程序内显示，不重复推送到 Bot 私聊。

## 私聊通道启用（兼容）

1. 更新代码、构建／重启 Go 后端，并更新仓库中的管理员静态资源。所需 PostgreSQL 表由后端自动初始化。
2. 在面板原有 Telegram 设置中配置并启用 Bot，在 AI 运维设置中配置可用模型与中转。
3. 打开 **AI 运维 → Telegram**，选择默认模型、权限模式、流式更新和完成通知，启用并保存。
4. 点击 **更新 Webhook**。这会给现有 Webhook 添加独立的 `secret_token` 验证，不另建 Bot，也不移除原来的工单／检测功能。
5. 管理员为自己或指定员工的后台账号 ID 生成一次性绑定命令，交给对应人员，在 Bot 私聊中发送 `/aibind <code>`。绑定码十分钟有效且只能使用一次。
6. 发送 `/ai` 进入 AI 模式，然后直接输入任务。进入后台刷新绑定列表，核对数字 Telegram ID 与后台账号。

旧的 `/bind <订阅地址>` 只绑定普通用户功能，**不会授予 AI 运维权限**。不要把一次性运维绑定码发到群聊或交给他人。Bot 配置“就绪”不代表 Telegram Webhook 已成功投递，首次启用后应实际私聊验证。

## 私聊用法

| 命令 | 用途 |
| --- | --- |
| `/ai` | 进入 AI 输入模式，之后直接发送自然语言任务 |
| `/ainew` | 下一条消息新建会话，使用后台最新默认模型与权限 |
| `/aisessions` | 列出最近会话，点击按钮切换 |
| `/aimodel` | 选择已配置的模型，不改变会话权限或推理强度 |
| `/aidetails` | 查看当前会话状态和操作摘要，完整记录在网页查看 |
| `/aistop` | 取消尚未启动的消息，并请求停止当前任务 |
| `/aiexit` | 返回普通 Bot 输入模式，不自动停止已有任务 |

常用操作也提供私聊按钮。在逐次确认模式下，会先完整分段发送操作对象、原因和参数／命令；全部操作卡发送成功后，才允许批准或拒绝。默认完全访问沿用现有工具授权，不要求逐次点击。

## 会话与权限

- TG 会话出现在现有网页会话列表，标记为 `TG`，可以在网页继续查看、对话或停止。
- 员工只访问本人会话，不允许删除会话、修改 AI／TG 配置或推理强度。管理员可查看与删除全部会话、管理绑定；员工可撤销自己的绑定。
- 默认完全访问由管理员配置；逐次确认使用同一套动作审批，不绕过原有授权及版本检查。
- 支付通道配置的限制保持不变。模型和 Telegram 不会获得新的任意数据库执行入口。
- “新建会话”不会删除旧记录；“退出 AI 模式”返回普通 Bot 功能。
- 同一会话已有任务运行时，不会悄悄排队新的修改请求；先等待或停止，再发下一项任务。

## 可靠性与停止

- Webhook 输入持久化去重，以 Bot 和 update ID 标识一次请求；原始任务参数加密冻结，业务请求使用稳定幂等 ID。
- TG 消息发送与 AI 执行分离。通知发送失败只能重试输出，不能因此重新启动模型任务或重放 SSH／后台写操作。
- Telegram 不提供发送消息的幂等键；若已发送成功但网络丢失响应，重试可能重复一条输出消息，不会因此重跑模型任务或后台操作。
- 回复按节流周期更新同一条消息，长正文分段；工具参数、完整工具输出和执行详情默认留在后台。
- 关闭“任务完成通知”仍会发送完整结果，只是不另发完成提醒；开启时额外发送一次简短通知，避免依赖编辑消息触发 Telegram 提醒。
- 服务器进程重启后会恢复尚未投递的结果和可确认的任务状态；不能安全判断的执行会标记中断／结果待核对，不承诺自动重跑远程修改。
- 停止、撤销绑定或禁用接入会阻止相关任务继续执行。已经完成的修改不会回滚，已在远端独立运行的进程不保证被终止。
- 后台删除会话会清理该会话的桥接内容并阻止旧 update 重建任务；已经发到 Telegram 的聊天消息不保证同步全部删除。

## 部署注意

- 新的 AI 指令要求 Telegram 请求携带 `X-Telegram-Bot-Api-Secret-Token`。反向代理需保留该请求头，不记录其值；旧 URL 的 `access_token` 单独不足以授权 AI。
- Webhook Secret 与应用 `APP_KEY`、Bot Token 绑定。更换其中任一项后，需要重新点击“更新 Webhook”。不要随意更换 `APP_KEY`，已有加密数据依赖该密钥。
- 模型执行和 TG 投递均在后端运行，不要求浏览器或手机保持在线。后台关闭或禁用 Bot 后，不应继续依赖 TG 接收结果。
