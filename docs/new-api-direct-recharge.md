# Forest 直接充值 AI 余额

## 使用与金额口径

Forest 的 AI 概览提供两条独立路径：

- **直接充值 AI 余额**：使用 Forest 已启用、受支持的在线支付方式；充值本金进入当前用户已绑定的 AI 账号。若支付渠道收取手续费，会与本金分开列出，手续费不增加 AI 余额。
- **转入 AI 余额**：继续使用原有 Forest 账户余额划转，不变更其行为。

金额统一用人民币展示，接口金额均为整数分。复用远端 CNY 报价和原单的精确 quota 核验；**不修改 New API 已有配额单位或汇率常数**，不重估历史余额。

直接充值不修改 `v2_user.balance`，不创建套餐/普通充值 `v2_order`，不进入原返佣计算。此前讨论的 AI 返利不在本次实现范围。

## 接口

路径均为 `/api/v1/user/new-api/` 下的鉴权工作区接口：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `recharge/options` | 查询金额范围和可用付款方式，无建单副作用 |
| POST | `recharge/create` | `{amount_fen, request_id}`，绑定本人 AI 账号，准备独立充值单 |
| POST | `recharge/checkout` | `{trade_no, payment_id}`，取得该订单付款入口 |
| GET | `recharge/detail?trade_no=...` | 仅查看本人的充值单 |
| GET | `recharge/orders?current=1&page_size=20` | 分页充值记录，与余额划转记录分开 |

禁止客户端指定目标用户、AI 用户、实际到账数量、付款金额或到账成功状态。写接口严格解码，仅接受声明字段。

## 状态与资金保护

1. 服务端核对 AI 账号归属、人民币报价，持久化用户请求 ID，再创建并验证 New API 原充值单。
2. 原单核对通过后状态为 `pending`，才允许取得 Forest 付款入口；同请求 ID 重发不会再建单，改金额会被拒绝。
3. 首次付款方式、手续费固定。付款入口持久化并复用；通用支付接口也执行相同并发/重放保护，不能绕过独立入口。
4. 原支付网关验签后，独立充值账本再次核对支付方式和本金加手续费。事务内置为 `paid_pending_credit`，重复通知不重复入账。
5. 后台任务持续向**原 New API 充值单**发送到账通知，并回读原单状态、金额、额度和账号归属。远端成功才置为 `succeeded`。
6. 远端短暂故障保持“已支付 · 到账中”，退避重试同一原单；通知响应丢失时先回读核对，不创建替代单。关闭浏览器或重启进程不丢失已支付任务。

支付回跳仅用于打开记录，绝不作为付款证据。前端代理为充值收银台转发自己观察到的站点 Origin，回跳到 Forest 前端，而不是后端域名。

`v2_newapi_checkout.funding_source` 将 `wallet` 与 `direct` 隔离，同一远端原单只能属于一种资金来源；现有钱包付款接口拒绝直接充值原单，避免两条链路同时出资。

## 依赖与运维边界

- 后端启动自动创建独立 `v2_newapi_recharge` 表及索引，现有账本不清理或重建。
- New API 须启用已有 Forest 桥接、正确的管理员核对权限、人民币分报价及充值功能。其 `alipay` 名称可能仅代表钱包桥，并不意味着该站配置了独立支付宝通道；实际外部收款仍复用 Forest 支付。
- 必须同时更新后端和前端；不需要为本功能更换 New API 的全局支付地址。上线前还需在真实渠道完成小额支付验收。
- 本地测试使用隔离 PostgreSQL schema、模拟 New API 和签名支付通知，不代表真实资金已完成生产支付验收。
- 原单创建请求结果不明时保存 `prepare_unknown`，不接受外部付款，也不盲目重建。这类记录目前需管理员核对，尚无自动匹配原单/取消的界面。
- 未付款订单目前没有自动取消/过期结案流程。未完成的充值会阻止切换 AI 站或商户，避免已发付款链接指向丢失的目标；凭据可在同一站点/商户下轮换。
- 付款入口结果不明时保留状态查询，不自动重试可能已生效的外部操作。记录中仅保存去敏错误类别，不回显商户密钥、AI 管理令牌或完整远端异常。

## 本地验证

对专用、可丢弃的 PostgreSQL 设置 `FOREST_NEWAPI_TEST_DSN` 后，在 `go-api` 运行：

```sh
go test ./internal/newapibridge ./internal/payment ./internal/http ./cmd/server
go test -race ./internal/newapibridge -run Recharge -count=1
```

Forest 前端使用其测试脚本，浏览器用独立 context 拦截充值接口；不可将测试 mock 注入正常使用的站点。

本次本地验收（2026-11-11）：

- 专用 PostgreSQL 实跑 12 个充值主测试（含并发、签名网关回调、失败补偿子场景），并通过 newapibridge/payment/http/server 全包 `-race` 回归。
- 前端 New API 相关 106 项测试通过；前后端路由契约与 TypeScript 检查通过。
- 浏览器覆盖 320/390/768/1440 宽度、同请求恢复、扫码、到账状态及付款回跳；既有余额划转、聊天、密钥等工作区回归通过。
- 未提交真实付款、未推送或部署；上线还需更新两端并进行真实小额支付核验。
