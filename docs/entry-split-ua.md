# ID 范围＋UA 的固定二分

在「节点管理 → 入口分配」中，包含**一个用户 ID 范围和零至多条合法 UA 条件**的普通覆盖入口规则，可通过「更多 → 转换为固定二分」转换。转换时填写 A、B 两组入口即可。

## 名单与请求条件分别处理

- 名单：取转换时 ID 范围内实际存在的用户，按 ID 顺序平均分成 A、B 两个静态组，奇数时 A 多一人；仍要求至少两人。
- UA：保留原条件，每次请求实时检查。多个条件之间是 AND；单条「包含任意关键词」内部仍为 OR，大小写和空 UA 行为沿用原规则引擎。
- 用户在固定名单中且请求 UA 满足条件时，才使用所属子组入口；UA 不匹配时继续后续规则或默认入口逻辑。未分配用户不会因为 UA 匹配而自动入组。
- 不使用历史日志或最近一次 UA 筛选用户名单，不要求用户先使用指定客户端拉取。一个账号可以使用不同客户端，UA 限制应作用于请求而不是固化为账号属性。
- 固定名单人数不等于当前使用该 UA 的人数，也不是同时在线人数。新增用户不会自动进入已建立的静态快照。

例如 ID `100–200`、UA 包含 `Forest`：先将这个范围内现有账号分成 A/B；同一账号通过 Forest 拉取时走所属 A/B 入口，改用不符合条件的 UA 时继续后面的规则，不会被固定分组强制接管。

## 继承及兼容

原规则名称、生效节点、优先级、启停状态和域名解析设置沿用原逻辑。继续二分、自动二分、修改叶子入口及合集地址覆盖均不清除父规则的 UA 条件。UA 条件是整套固定分组共享的请求限制，界面在子组列表、编辑、名单和二分确认处只读显示，不提供按叶子改写父级 UA 的操作。

管理员模拟、员工入口预览及订阅防护组合筛选，与真实订阅使用同一套请求条件判定。订阅防护查询没有实际 UA 时保留「无法确定」提示，不把未知 UA 当成一次真实空 UA 请求。

原有纯 ID 范围或近期用户固定二分行为保持不变：保留的旧 ID 条件只记录名单来源，用户归属继续以保存的 assignment 为准，不重新动态按范围分配。附加套餐、邮箱、注册天数、第二个 ID 范围等条件的转换仍不支持；隐藏／原地址规则以及附带额外节点的规则仍沿用原有转换限制。

## 部署与验证

需要同步更新 Go 后端与后台 `admin.js`。不增加数据表、字段或日志，不修改用户网站／App 接口。

常规回归：

```sh
cd go-api
go test ./...
go test -race ./internal/cliententry ./internal/user ./internal/admin ./internal/http
go vet ./...
cd ../admin-src
npm run check
node --test scripts/test-*.mjs tests/*.test.mjs
npm run build
```

真实数据库集成测试必须使用**专用、可丢弃的 PostgreSQL 数据库**，先导入 `database/install.pgsql.sql`（该安装脚本会重建表，严禁对生产库执行），再配置 `FOREST_SPLIT_UA_TEST_DSN` 运行：

```sh
cd go-api
go test ./internal/admin -run '^TestClientEntrySplitUAPostgresIntegration$' -count=1 -v
```

测试验证真实 SQL 转换与静态人数、同一用户的匹配／不匹配／空 UA 下发、管理员模拟及订阅防护的一致性，以及继续二分、改入口、加入合集后 UA 限制仍生效。
