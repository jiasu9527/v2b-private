# AI 运维中途停止与部署知识修复（2026-11-02）

## 现象与证据

- 线上失败轮次 272 在第 8 次模型请求中断：最后工具结果为 UTC 11:48:25，失败为 11:48:55，错误为“AI 流式响应中断或超出限制，未执行工具”。该次操作没有用户停止标记。
- 配置的灾备超时为 30 秒，旧代码将它用于整段请求的 context deadline；下一轮 273 又因所有中转处于 60 秒冷却立即失败。没有上游逐帧抓包，不能判断失败期间是否有数据分片，因此同时修复首响应等待和持续流超时。
- 后续轮次已经继续成功，补丁不重放旧任务，也不根据日志内容重新执行入口修改。
- 知识库旧校验会拒绝正文中的显式 key/token/password，部分变量占位符也会命中；聊天输入中的脚本变量还可能触发 SSH 登记解析。不能把这些拒绝等同于知识数据库故障。

## 修改

1. 模型首段正文至少等待 90 秒；开始接收后采用可续期的空闲超时。单次 completion 连同等待、切站和重试最多 5 分钟，整轮完全访问任务不增加工具次数或总时长限制。
2. 临时失败优先切换健康中转，再有限重试同站；全部冷却时可取消地等待最近一个恢复。只有完整校验后的工具请求才能执行，之前完成的工具不重放。
3. 明确输出长度截断时逐级增加预算；空白回复不得标为正常完成；不同尝试的流式草稿不拼接。
4. 知识正文允许原样保存部署脚本及 key，新增加密正文列，去敏索引用于搜索；详情按原权限解密。含凭据正文不自动注入无关会话。
5. 明确的安装脚本保存请求不走 SSH 登记；原请求加密，知识工具历史保存去敏副本，当前模型上下文保留可用原文。历史脱敏脚本必须重新通过知识工具读取，不得直接执行。

不会放宽员工设置／删除权限或支付配置禁区；不会自动覆盖已有知识版本。加密使用现有 APP_KEY，须随数据备份并保持稳定。SSH 动作命令、远程输出及旧备份不属于本次全面加密承诺。
