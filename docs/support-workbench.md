# 员工工作台（现有员工权限）

## 使用

1. 直接复用现有用户的「是否员工」开关，即 `v2_user.is_staff`，不新增角色、不需要额外添加员工或配置目标入口授权。
2. 管理员在「用户 → 用户管理 → 用户列表」编辑已有账号，开启「是否员工」。已有员工账号可直接使用，无须重新配置。
3. 员工从同一个后台地址登录，默认进入「入口状态」，仅有「入口状态 / 精准查询用户 / 我的操作记录」三个页内选项。
4. 所有未封禁、非管理员的员工均可精准查询普通用户，修复套餐、总流量配额及有效期，或加入已有的指定邮箱入口组、退出指定恢复默认规则。不能查询、操作管理员或其他员工账号。
5. 管理员在「用户管理 → 员工操作记录」页内选项查看全部单用户权益和入口变更。原 `/support/staff` 页面只兼容打开此记录选项，不再有独立权限配置页面。
6. 关闭「是否员工」或封禁账号即撤权。修改员工/管理员身份时会撤销该账号会话，需重新登录；普通资料修改不强制退出。管理员身份优先，即使同时开启员工开关也仍进入管理员后台。

本模块不改网站用户前端，不要求 App 新增接口。已有 `user/checkLogin` 兼容 query、JSON、form 的 `auth_data`，返回 `id`、`email`、`is_staff` 身份字段；原管理员字段保持兼容。

这是直接调整原员工权限，而不是并存两套员工。旧 `/staff/*` 管理接口仍不向员工开放，补单只能通过字段白名单的专用员工接口完成，不能绕过工作台修改密码、邮箱、余额、角色、公告、工单、批量封禁或群发邮件。管理员原有能力保持不变。权限校验实时读取数据库，后台缓存不能延长已撤销的员工权限。

Telegram 同步收紧：员工保留绑定、个人流量等用户功能，以及查看已有入口检测结果；主动发起检测、整组入口二分、回复全站工单和接收全站管理通知仅限管理员。历史消息中的按钮也重新检查当前角色，不会因旧按钮保留额外权限。

## 套餐、流量及有效期补单

- 精准查询后展示当前套餐、总配额、上传/下载用量和有效期；只能显式选择要修改的字段，不把未选择字段一并覆盖。
- 可选现有套餐（包括停售套餐，以便修复历史客户）。改为不同套餐时同步套餐节点权限组、设备/速率限制及默认配额；显式提交总配额时以提交值为准。
- 总配额接口单位是 bytes，页面以 GB（1024³ bytes）编辑。修改总配额不会自动清零用量；只有勾选「重置已用流量」才重置当前上传/下载计数。
- 有效期支持指定时间或 `null`（永久）；不提交该字段就保持现状。修改套餐不会自动延长有效期或重置用量。
- 这是人工修复权益，不自动生成订单、支付成功流水、收入或佣金；实际支付问题仍应核实原订单和支付渠道。
- 提交绑定当前权益配置 `expected` 哈希；其他员工、管理员或支付回调已改权益时返回 409。日常流量增长不会阻碍只改有效期，非重置操作也不会覆盖新增用量。

## 入口分组的生效边界

- 直接复用「节点管理 → 入口分配」中现有的指定邮箱名单，不再新建用户地址覆盖。允许加入的组为已启用的标准覆盖入口规则，且恰有一个 `email / in` 条件；用户还须满足该组其余条件。不支持指定邮箱的普通规则、固定二分/快照组、隐藏规则等不提供加入。
- 加入时将用户完整邮箱加入目标组，并从其他可编辑的指定邮箱组退出；保留其他用户邮箱和所有非邮箱条件，不要求源/目标拥有相同节点集合，也不修改全站规则排序。
- 邮箱名单忽略大小写。若历史账号存在同一规范化邮箱对应多个用户（包含管理员/员工），拒绝入组/退组，先由管理员处理邮箱冲突，避免一次操作影响多个账号；按 ID 修复该用户权益不受此限制。
- 「退出指定组，恢复默认」从上述邮箱名单（包括停用组）移除此用户，并撤销旧版地址覆盖。最后一个邮箱退出后保留空邮箱名单条件，匹配空集；绝不删除条件变成全员规则。管理员也可保存空邮箱名单供后续加人。
- 默认逻辑仍按现有套餐节点权限、条件、UA、固定名单和第一命中顺序决定下发，员工不能借入组编辑规则参数或套餐节点权限。名单加入不等于所有客户端立即命中；界面分别展示当前组和当前 UA 下的实际命中情况，被更早规则覆盖、用户无可用节点或其他条件不满足时不能视为已经切换。
- 原规则入口地址、节点成员和附加节点都按该组自身配置执行，后续管理员改组配置会自然跟随。退出不会移除非邮箱规则的自动匹配或固定二分快照分配。
- 指定邮箱持续保留到退出或管理员修改名单，不再提供额外的 1 小时/24 小时临时覆盖。生效依赖用户更新订阅，不会强制切换已建立连接。
- 同时提交使用用户行锁、规则行锁以及 `version` 校验；规则名单采用事务内合并，不覆盖其他用户的并发名单修改。两类变更共用 `request_id` 幂等键，相同内容重试不会重复变更和写记录，内容不同返回 409。
- 管理员编辑规则仍属于全量保存；如果在员工操作前已经打开旧规则表单，应先关闭并刷新后再编辑，避免用旧表单覆盖新的邮箱名单。

## 检测首页

- 仅展示「入口分配」已纳入监测的 TCP 入口，未监测入口不显示、不计入统计；按规范化地址和端口去重，不同域名即便解析为同一 IP 也不合并。
- 主表显示唯一入口，展开查看关联规则/固定组，再展开查看各探针、阈值、检测时间及错误。
- 状态包括正常、部分异常、异常、过期/未知和停用；异常或未知排前面。同一入口只聚合已配置监测的来源，不会因为其他规则未纳入监测而降级为部分异常。已纳入监测但无结果、数据过期、探针离线或目标待同步的入口仍显示为未知，不能误当正常或直接隐藏。
- 页面每 30 秒刷新已有结果，不因刷新触发即时探测或配置变更。
- 覆盖范围为入口分配中普通独立入口、固定分组叶子入口及 original 规则对应原节点；独立「客户端入口」配置和其他未关联节点不在此检测范围。
- 后端只读 DTO 不包含探针密钥、远程登录资料或完整管理员配置。

## API

成功响应包含 `data`，错误响应包含 `message`，敏感响应 `Cache-Control: no-store`。员工接口使用现有登录会话，推荐 `Authorization: Bearer <auth_data>`。写接口仅接受 `Content-Type: application/json`，认证字段不得混入 JSON。

员工接口（独立于管理员路径）：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/v1/support/overview` | 去重入口健康总览 |
| GET | `/api/v1/support/user?query=完整邮箱或ID&ua=可选UA` | 单用户精准查询；不支持列表、模糊或导出 |
| POST | `/api/v1/support/entry` | 加入指定邮箱入口组/退出指定恢复默认 |
| GET | `/api/v1/support/entitlement/plans` | 可选套餐及默认流量配额，不含财务数据 |
| POST | `/api/v1/support/entitlement` | 修复单用户套餐、配额、有效期或重置已用量 |
| GET | `/api/v1/support/operations?page=1` | 本员工实际权益/入口变更记录，每页 20 条 |

指定请求：

```json
{
  "user_id": 123,
  "target_key": "policy:20",
  "restore": false,
  "reason": "用户连接排障",
  "version": 123456789,
  "request_id": "8c287040-1d1f-4e56-b6a7-a960eab5d267",
  "ua": ""
}
```

退出时 `restore=true`、`target_key=""`，提交当前 `entry_membership.version` 和新的 `request_id`。`source_policy_id`、`expires_at` 仅保留解码兼容且必须为 0，旧版指定地址请求不会继续执行。

查询结果包含 `user`、`entitlement`、`entry_membership`、`scopes`、`ua`：
- `entitlement` 含 `user_id,plan_id,plan_name,group_id,transfer_enable,u,d,expired_at,device_limit,speed_limit,version`。
- `entry_membership` 含 JS 安全整数 `version`、可加入 `targets`、`current_groups`（`policy_id,name,entry_host,enabled,effective`）及 `has_legacy_override`。`effective` 表示当前预览至少一个节点确实命中该规则，不承诺整组所有节点都命中。
- `scopes` 仍展示现有规则实际命中的线路范围，兼容旧覆盖信息；不能把组名单存在或旧 `override.active` 当作已经生效。

补单请求示例（只有明确提交的字段参与修改）：

```json
{
  "user_id": 123,
  "plan_id": 2,
  "transfer_enable": 107374182400,
  "expired_at": 1800000000,
  "reset_usage": false,
  "expected": "<查询结果 entitlement.version>",
  "reason": "已核实付款，修复遗漏权益",
  "request_id": "9c287040-1d1f-4e56-b6a7-a960eab5d268"
}
```

`expired_at:null` 设永久，不提交表示不改；`plan_id` 只能选择存在的正整数套餐，不能借此修改身份/余额。补单成功返回最新 `entitlement` 快照，界面再精准刷新用户及入口分组。日志 `before_state/after_state.kind` 为 `entitlement` 或 `entry_membership`，旧日志格式继续兼容；内部幂等指纹不返回。

管理员接口前缀 `/api/v1/{secure_path}`：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/support/operations?page=1` | 全部员工的权益/入口变更记录 |

身份通过原用户管理接口中的 `is_staff` 字段设置，没有独立的员工添加、启停或目标授权 API。

错误：400 参数/格式；403 会话/角色失效或操作未授权；404 用户不可操作；409 版本或幂等冲突；415 非 JSON；429 限频。精准查询每员工每分钟 30 次，变更每分钟 20 次；限频仅保存每员工每动作一个计数器，不记录查询内容。

## 部署与记录保留

Go 服务启动前自动幂等创建 `v2_support_request_limit`、`v2_support_entry_override`、`v2_support_operation` 三张业务状态表，不创建独立员工授权表。需要更新 Go 二进制及 `public/assets/admin-new` 构建产物，重启后生效。旧版本如曾创建 `v2_support_staff`，其记录不再被读取、也不会自动提升普通账号；为避免破坏历史配置，升级不会自动删除旧表。

成功补单、加入或退出与结构化操作记录同一事务；无实际变化不写日志。不写搜索、查看、轮询日志，不存完整请求体或用户凭据。变更记录保留 90 天，由现有每日维护任务分批清理。关闭员工开关不会抹掉历史记录，也不会自动撤销此前有效的用户权益或邮箱名单。

## 验证

```sh
cd go-api
go test ./...
go test -race ./internal/admin ./internal/user ./internal/http ./internal/session ./internal/telegram -count=1
```

可选真实 SQL/订阅链路验收测试：先准备**一次性测试数据库**并导入 `database/install.pgsql.sql`，再设置 `FOREST_SUPPORT_TEST_DSN` 运行 `go test ./internal/admin -run '^TestSupportPostgresEndToEnd$' -v -count=1`。未设置时跳过；测试会创建并清理自身样例。该测试也可连接兼容 PostgreSQL 协议的隔离 PGlite 实例；此时不能据此声称已验证真实多实例数据库锁竞争。
