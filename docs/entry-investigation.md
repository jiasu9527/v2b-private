# AI 对话入口泄露排查

本功能复用历史实际下发、冻结档案和证据二分。进度存在数据库，后台持续更新报告，不依赖某次 AI 会话。它用于缩小需要复核的账号范围，不认定账号本人责任，不自动封号。

> 无内鬼提取 A 组确定被墙了，帮我按实际下发用户排查，用健康 IP 池二分。

AI 自行查目标、时间证据、节点和 UA，冻结名单、启动任务、预览分流，再按当前会话权限执行并核对。你不需要去页面填写档案 ID、哈希、版本或导出用户名单。未指定时沿用默认 24 小时 / 10 轮 / 8 人阈值。

- **完全访问**：沿用已授权的排查范围连续执行，不对每一步再弹一张确认卡。
- **逐次确认**：保留你已选择的操作审核模式，不因聊天指令自行提升权限。
- 用户在聊天明确确认“被墙”、异常时间或对照结果即可作为核实来源，不用再去页面勾选。目标有歧义或关键证据缺失才集中追问；未知对照仍记为 unknown，不能编造正常。
- 后续说“看看这组进度”“A 组也墙了，继续排查”，AI 读取已有任务续办，不重建名单。
- 后台独立更新报告；不会在聊天结束后自动唤醒 AI 执行未来下一轮。仅问状态或方案不授权变更入口。

## 可选页面流程（不是使用 AI 的前提）

1. 在入口排查中选择故障 IP 对应的规则或固定叶子，查询从本轮启用至首次异常的实际下发记录（包含开始，不包含结束），核对节点、端口、UA 后冻结档案。
2. 打开档案内的「半自动排查」。人工确认已排除源站监听、机房故障等原因，填写核实依据；异常时间必须与查询结束时间一致。
3. 默认每轮最短观察 24 小时、最多 10 轮、候选不超过 8 人转人工复核。可在启动时调整。观察时长不是连续健康证明。
4. 使用既有二分预览核对 A/B、未选用户 R 的去向与优先级，选择健康备用 IP 池或两个已完成健康检测的独立 IP。人工确认执行才改变入口。不会删除原规则、合集或自动封禁用户。
5. 对每组分别展示分配人数、实际下发去重人数、未记录下发人数及异常前已下发人数。人工登记封锁时间、核实依据，以及未向用户下发的对照入口状态。
6. 仅在单组异常有实际下发依据、另一组检测正常、对照由人工确认正常且观察条件满足时，可「预备下一轮」。后端冻结名单，不需要 AI 复制成千上万个用户 ID；此动作本身不改入口。新档案还要再次预览并人工执行。

继续 A 不等于排除 B。父轮 B 继续接受观察与核实；B 异常、监测丢失或过期、名单或范围改变都会暂停子轮推进。已确认内容可追加修正，保留此前核实记录；修正后与旧冻结窗口不一致的子轮不得继续。

## AI 操作

以下操作已加入 `entry_evidence` 目录：

| 操作 | 作用 |
| --- | --- |
| `investigation_list` / `investigation` | 只读已保存的任务与报告 |
| `investigation_start` | 对未执行的根冻结档案启动任务 |
| `investigation_refresh` | 重新分析现有记录，不主动探测、不换入口 |
| `investigation_confirm` | 保存人工核实的分支异常和对照状态 |
| `investigation_next` | 在服务端冻结下一轮并记录父子关系 |

`investigation_start`、`investigation_confirm`、`split_execute` 与其他 AI 操作一样沿用当前会话权限，不设额外的排查专用确认门。原 `candidates`、`freeze`、`split_preview`、`split_execute` 流程继续复用，名单和版本仍由服务端校验。所有操作沿用管理员/员工鉴权，撤销授权和停止任务继续生效；普通用户不可读取排查数据。结果未知时先用纯只读 `cases` / `investigation` 核对，不能盲目重放。

后台每 5 分钟处理至多 20 个任务，按最早检查时间轮转；任务多时单任务刷新间隔会更长。页面每分钟读取已保存报告，不代表每分钟重新检测。单个任务分析失败不阻塞其他任务，也不代替证据归档成功后才允许清理日志的约束。

## 首版边界

- 仅支持实际 IP 的已启用 override 规则或独立固定叶子。规则须满足既有证据二分限制（标准规则为一个 user_id 范围及可选 UA）；合集、额外节点等不能安全表达的范围明确拒绝，不强行合并。
- 新 IP 必须在对应端口具有新鲜健康结果，不能被其他规则、合集、入口组、节点原地址或客服覆盖使用；保留期内已下发或历史排查用过的 IP 不作为独立实验入口。
- 普通下发日志默认保留 7 天，沿用现有可配置设置。窗口超出保留范围、归档缺口、共享/名单外暴露等会阻断继续缩小；已发现的暴露风险保存到任务，不随普通日志删除消失。不能保证保留期外从未暴露。
- 对照状态是操作人的核实结论，首版没有自动创建、检测或验证独立对照入口。
- 完整成功响应只证明服务端返回了入口，不能证明客户端导入、连接，也不能证明是谁泄露。未记录下发不等于没拿到；暂时正常不等于无嫌疑。
- R 保留原入口并不等于故障恢复。业务恢复需另外规划；本功能不会自动为全组换 IP，也不会自动删组回收 IP。
- 小名单、双分支异常、轮数上限或证据不足交人工复核。首版尚无任务暂停/关闭接口，关联任务档案受到删除保护。

新表 `v2_entry_investigation` 在服务初始化时自动建表，保存任务设置、人工核实追加记录、报告和轮次关联。不存订阅凭据。更新代码并重启后端后生效；推送 GitHub 不会自动部署生产。
